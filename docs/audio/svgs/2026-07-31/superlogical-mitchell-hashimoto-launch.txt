欢迎收听每日技术学习语音讲解。本期主题，隐退三年后杀回来：HashiCorp创始人官宣二次创业，这次要做「万物的多路复用器」。标签包括Superlogical、Mitchell Hashimoto、终端多路复用、人机协同。本次讲解预计时长 约 11 到 12 分钟，共 10 个部分。好，我们开始。

一句话概括。本文解决的核心问题是：Mitchell Hashimoto 离开 HashiCorp 三年后为何选择从「终端多路复用器」切入二次创业，以及 Superlogical 试图用「围绕工作本身的持久会话」弥合本地、远程、沙箱、生产与 AI Agent 之间割裂的工作层。

接下来，第一部分，核心概念关系。

关系脉络如下：① 现代化，终端多路复用器，然后② 可组合，composable 架构，然后③ 生产级，安全运行，然后终局：万物，工作多路复用层

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「终端多路复用器是个小众赛道」——Mitchell 的赌注是终端连接开发者、AI Agent、工具链与基础设施，是承载后续「工作多路复用层」的地基，而非终局产品本身。

接下来，第三部分，反驳。

反驳

对立视角：基础设施保守派 / 「终端已死」论者

云 IDE 与全托管 Agent 正在吞掉本地终端场景——再做一个更炫的多路复用器，可能只是给即将被平台托管的工作流打补丁，而非重新定义协议。

接下来，第四部分，【概念拆解卡】工作多路复用层与持久会话。

在讲什么问题，构建软件已横跨本地、远程主机、沙箱、CI 与生产；工作模式从人机交互扩展到自动化任务与 Agent 并行，但现有工具把交互式、自动化、生产管控切成孤立系统。

核心机制，缺失层应是围绕「工作本身」的持久 session——跨应用与环境、默认携带上下文、暴露结构化数据与操作接口、保留完整历史，既可被软件驱动又对人可见可控。

关键理解，AI 放大了割裂的代价，但割裂根源于几十年来的系统管理、CI 与远程协作边界，并非 AI 独有制造。

典型场景，开发者关终端换设备续接现场；多人实时共享同一会话；Agent 与人类在同一工作层并行操作。

边界说明，第一步聚焦终端多路复用器体验（滚动、选中、翻页、Web/原生客户端），更大版图尚未公开细节。

「缺失的那一层，应该是一个围绕工作本身构建的持久会话。」——Superlogical 官网表述

接下来，第五部分，【方法/工具卡】终端多路复用器 MVP 路径。

方法名：现代化 Terminal Multiplexer（第一步产品）

核心思路：把多个终端窗口组织进长存会话，关应用换设备可原样重连；内置实时共享会话能力。

操作步骤，① 基于 libghostty 构建；② 支持 Web + macOS/iOS 原生客户端；③ 解决 tmux/Zellij 遗留的滚动选中翻页体验；④ 持续贡献通用终端能力回上游开源。

选型条件，需要跨设备持久工作现场、协作共享终端、为后续 composable 层打地基时优先关注 Superlogical 进展。

团队坦承单看「终端多路复用器」易被误解为窄赛道，但终端是连接一切的最小公共地基。

避坑：误以为 Superlogical 会改变 Ghostty 治理——Ghostty 已捐赠联邦认证非营利组织，使命与路线图独立，Superlogical 仅作为 libghostty 使用者遵循 MIT 协议。

接下来，第六部分，【跨概念对比表】现有割裂 vs Superlogical 愿景。

交互式工作，默认背后有人，会话随工具消亡，持久 session 跨设备续接，工作现场不再绑定单台机器

自动化任务，消失在日志与后台任务，结构化接口 + 历史可追溯，自动化与人机操作同一上下文

生产环境，独立权限与管控体系，第三步「安全在生产运行」，终局需打通管控，非一步到位

协作，共享会话多为后期补丁，第一天内置实时共享，协作是产品基因而非插件

技术底座，各工具自有实现，libghostty 可复用组件，开源地基 + 商业产品分层清晰

接下来，第七部分，【决策/选型表】何时关注 Superlogical vs 继续用 tmux/Zellij。

纯本地 Linux 服务器运维，继续 tmux/Zellij，成熟稳定、零迁移成本，立刻切换未发布产品，Superlogical 产品尚未 GA

跨 Mac/iOS/Web 持久会话，跟踪 Superlogical 发布，原生+Web 客户端是明确差异化，自建多平台同步，体验与维护成本极高

人机+Agent 统一工作层，关注其 composable 路线图，终局瞄准 Agent 并行作业，仅用终端模拟器凑合，缺乏结构化接口与历史层

投资/生态判断，参考 HashiCorp 路径，Glenn Solomon 二次押注 + Stripe/Shopify 天使，忽视开发者体验赛道，Mitchell 履历证明 DX 可做大生意

接下来，第八部分，【心法/原则卡】连续创业者的「为爱发电」逻辑。

原则，真正被开发者尊敬的作品往往源于「市面上现有方案不够满意」——而非先有商业计划。

为什么重要，Ghostty 从个人项目到百万日活再捐赠非营利，证明 Mitchell 的动机与 HashiCorp 时代一致：消除开发者与真正想做的事之间的摩擦。

怎么落地，观察 Superlogical 是否持续 building in public、libghostty 上游贡献质量、团队（Jack Pearkes/Alasdair Monk/Hector Simpson）交付节奏。

适用边界，对仅需稳定终端的用户，现有工具足够；对押注「人机协同底层协议」者，才需深度跟踪。

接下来，第九部分，总结与行动。

结论

Mitchell Hashimoto 二次创业 Superlogical，种子轮 1000 万美元，Notable Capital 与 Amplify Partners 领投。

切入点：现代化终端多路复用器；终局：覆盖本地/远程/沙箱/生产/Agent 的工作多路复用层。

技术基于 libghostty（MIT），Ghostty 非营利使命与治理不受影响。

创始团队含 HashiCorp 一号工程师与多位资深 DX 设计负责人；投资人含 Stripe/Shopify 联创等。

Glenn Solomon 12 年后再次首支票押注同一位创始人，看重其开发者尊敬度与做大生意的双重特质。

订阅 Superlogical / Mitchell 博客与 building in public 更新，跟踪第一步产品发布节奏。

评估团队是否需跨设备持久终端会话，对比 tmux/Zellij 与 forthcoming 原生/Web 客户端。

若使用 Ghostty/libghostty，关注上游通用贡献是否持续，避免与商业产品路线混淆。

对 Agent 编排架构师：预留「结构化工作 session」抽象，而非把 Agent 状态散落在各工具日志里。

投资与生态观察者：将此次创业视为「开发者体验」赛道再次被资本验证的信号。

总结

关键认知转变

终端不是衰退中的怀旧工具，而是 AI 时代人机协同的枢纽；多路复用器的价值在于把被割裂的工作形态重新缝合成可持久、可协作、可自动化的统一层。
