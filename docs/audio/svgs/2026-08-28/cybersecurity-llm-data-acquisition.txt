认知纠偏

常见误解：「只有千亿参数模型才能在安全领域出彩」。VulnLLM-R 论文证明，7B 规模模型经精心数据微调，在漏洞检测任务上同样取得不俗效果——精耕细作的小模型路线对资源有限但想打造简历亮点的同学更务实。

接下来，第三部分，反驳。

反驳

对立视角：「通用大模型已够用」派 / 闭源 API 依赖者

Claude 在逆向和漏洞挖掘上已展现惊人能力，你再堆七类异构语料训一个 7B 小模型，投入产出比远不如直接调 API 加 RAG——垂直模型是资源不足时的妥协，不是安全赛道的最优解。

接下来，第四部分，【概念拆解卡】网络安全语料的三大鲜明特点。

在讲什么问题，安全领域数据与通用语料不同，采集前必须理解其分布特征。

核心机制，分散（论文在学术库、标准在官网、漏洞在数据库、实战经验在社区）、异构（PDF、JSON、博客 HTML 格式各异）、时效性强（新漏洞、新攻击手法需持续更新）。

关键理解，对目标领域知识体系和数据分布有深刻认知，才是数据工作的真正门槛，而非单纯会写爬虫。

典型场景，预训练阶段构建领域知识底座；微调阶段补充漏洞问答、攻防案例。

边界说明，本文聚焦「获取」，清洗与预处理在下一篇《预训练数据的处理》展开。

落地建议：启动项目前先画一张七类数据来源清单，按优先级分批采集，避免一上来就爬社区博客（噪声最大）。

接下来，第五部分，【方法/工具卡】电子书籍：系统化知识底座采集。

核心思路：优质专著结构清晰、逻辑严密，解析成 Markdown 后天然保留层级，是质量最高的语料类别之一。

操作步骤，

① 安全专业书：吴翰清《白帽子讲Web安全》、_The Web Application Hacker's Handbook_；

② 网络基础：谢希仁《计算机网络》、Stevens《TCP/IP 详解 卷1》；

③ 计算机基础：CSAPP、Silberschatz《操作系统概念》；

④ 按作者/出版社/版本/口碑筛选，试读目录与一章正文再入库。

选型条件，需要模型建立结构化知识框架时优先书籍，而非碎片博客。

避坑，劣质书术语前后不一，喂给模型等于教错误知识；贵精不贵多。

版权提醒：个人练手通常问题不大，商用务必确认授权范围是否允许用于模型训练。

接下来，第六部分，【方法/工具卡】学术论文与顶会：arXiv API 批量采集。

核心思路：论文提供原理基础、同行评审可信度、前沿时效性（大模型安全攻防、AI 漏洞挖掘等近两年方向）。

操作步骤，

① arXiv cs.CR 板块：免费检索 API，批量采集首选；

② 四大顶会：IEEE S&P、USENIX Security、ACM CCS、NDSS；

③ 用 Python urllib 调用 export.arxiv.org/api/query，解析 Atom XML 获取标题、摘要、PDF 链接。

选型条件，需要「为什么」层面的攻击防御原理、量化实验结论时选论文。

对比相邻方法，社区博客是「经验之谈」，论文结论是「测出来的」，模型表述更严谨、更少幻觉。

落地建议：搜索词示例 cat:cs.CR AND all:log4j，调节 max_results 控制批量规模。

接下来，第七部分，【方法/工具卡】NIST/MITRE 标准与 CVE/CWE 漏洞库。

核心思路：标准教模型「怎么做才规范」，漏洞库是安全大模型区别于通用模型的核心竞争力。

操作步骤，

① NIST SP 800 系列：官网免费 PDF，如 SP 800-61 应急响应指南；

② MITRE ATT&CK：官方 STIX JSON 全量下载，将 name/description/缓解措施拼装成自然语言；

③ CVE 官方 REST API：cveawg.mitre.org/api/cve/{CVE_ID}，无需鉴权；

④ CWE 全量 XML：cwec_latest.xml.zip 下载解析，近千条缺陷定义；

⑤ 大规模 CVE：GitHub CVEProject/cvelistV5 镜像仓库按年份筛选。

避坑，单条 API 无法满足大规模需求，需结合镜像仓库批量获取。

结构化字段可借助大模型转化为自然语言，例如：「CVE-2021-44228 是 Apache Log4j2 中的 JNDI 注入漏洞……」

接下来，第八部分，【决策/选型表】七类语料渠道选型指南。

建立结构化知识框架，权威电子书籍 + 基础教材，章节即知识图谱，层级清晰，大量低质拼凑书，术语混乱难以清洗挽回

理解攻击防御原理，arXiv cs.CR + 四大顶会，同行评审、实验数据背书，仅依赖社区经验帖，易产生幻觉、表述不严谨

规范合规输出，NIST SP 800 + MITRE ATT&CK，行业标准化知识体系，非官方转载摘要，可能过时或曲解原意

漏洞问答与修复建议，CVE API + CWE 全量 + Exploit-DB，CVE 记具体漏洞，CWE 分类缺陷类型，只靠通用语料，无法准确回答 CVE 编号类问题

鲜活实战案例，FreeBuf/安全客/厂商威胁报告，事件复盘价值超十篇论文，不做清洗直接入库，转载重复、广告、标题党噪声极大

快速构建问答数据集，EasyDataset 蒸馏 + Hugging Face 现成集，节省人力，VulnLLM-R 等已验证，不看 License 商用，合规风险

接下来，第九部分，【方法/工具卡】EasyDataset 全自动蒸馏操作流程。

核心思路：让闭源/超大模型把推理思路浓缩成高质量数据集，小模型拟合后在特定任务逼近大模型（如 s1 论文仅花约 50 美元蒸馏 Qwen2.5-32B）。

操作步骤，

① 创建项目，以知名书籍名称为顶级主题锚点，描述中填入完整目录；

② 进入「数据蒸馏」，得到「全自动蒸馏」，配置标签层级（2～4 层）与每层标签数、每标签问题数；

③ 启动后跟踪标签构建、问题生成、答案生成三阶段进度；

④ 可选手动逐级生成标签，人工介入把关。

选型条件，需要定制化、覆盖完整的领域知识树且资源有限时优先蒸馏。

避坑，层级过浅覆盖粗，过深则生成成本高，需根据训练需求调整右侧预览的问题总数。

接下来，第十部分，【避坑清单卡】数据采集常见陷阱。

坑 1：社区博客不清洗直接入库——FreeBuf 等渠道数据量最大、噪声最多。解法：下一篇专门讲清洗，此处先标记为重点关照对象。严重程度：致命（拉低训练质量）。

坑 2：书籍版权忽视——商用模型训练未确认授权。解法：查 License，个人练手与商用分开管理。严重程度：致命（法律风险）。

坑 3：只用 CVE 不用 CWE——模型只知「哪个产品哪个漏洞」不知「哪类缺陷」。解法：CVE 与 CWE 配套采集。严重程度：小心（理解深度不足）。

坑 4：开源数据集不看标签分布——与训练目标不匹配。解法：先查标签分布、数据量级、License。严重程度：小心（浪费算力）。

接下来，第十一部分，【跨概念对比表】CVE 与 CWE 的分工。

记录内容，具体某产品暴露的某个漏洞，漏洞属于哪一类缺陷，CVE 是实例，CWE 是分类

典型问题，「这个代码触发哪个 CVE？」，「缓冲区溢出/SQL 注入如何防御？」，问答场景不同，需同时覆盖

数据形态，REST API 单条查询 + GitHub 全量镜像，官方 XML 全量 zip，均提供结构化字段可模板化

语料价值，漏洞编号、厂商产品、修复建议，缺陷定义 + 代码示例 + 缓解建议，CWE 近千条成体系成因语料

结论

网络安全语料分散、异构、时效性强，七类渠道（书籍、论文、标准、漏洞库、社区、开源集、蒸馏）缺一不可

书籍贵精不贵多，需搭配网络与计算机基础教材；论文首选 arXiv cs.CR 与四大顶会

NIST/MITRE 提供规范知识，CVE/CWE 是漏洞问答的核心竞争力

社区博客价值高但噪声大，是后续清洗重点；EasyDataset 蒸馏可快速构建定制化问答集
