一句话概括。本文解决的核心问题是：OpenClaw 热度回落后，Pi 如何用「先验证再收纳」的 1.0 能力（含 MCP 反转与 Codemode）服务单人终端编码，又通过实验性 Pi Durable 把检查点、幂等与所有权树搬进 Agent 应用，支撑崩溃恢复与多人协作。

接下来，第一部分，核心概念关系。

关系脉络如下：Pi 1.0，单人终端编码 Agent，然后Pi Durable，任意 Agent 应用框架，然后存储 + 并行对话，+ 工具 + 执行环境

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「Pi 曾经反对 MCP，现在收编等于打脸」。原文三层逻辑是 MCP 生态已变、为 MCP 做的工具分层改造对 Jev/图像模型也通用，且团队希望参与塑造「可组合的 OpenAPI 式 MCP」，而非场外吐槽。

接下来，第三部分，反驳。

反驳

对立视角：「追新 MCP/多模型路由的集成派」

企业已押注 LangGraph/Temporal 等成熟编排，再引入 1.5 万行实验框架只是重复造轮子，极简反而缺权限与可观测开箱即用。

接下来，第四部分，【概念拆解卡】Harness 与 Codemode。

在讲什么问题，模型之外，让模型真正干活的运行时——对话存储、工具调用、执行环境、任务调度。

核心机制，Codemode 在 harness 受信任侧用 JS/WASM 沙箱编排工具；中间结果进会话记录而非反复塞进 LLM 上下文。

关键理解，官方 Linear+Jev 演示 331+ 次工具调用，上下文零浪费——编排脚本替代「一轮一轮 chat 调工具」。

典型场景，批量拉 issue、并发情绪分类、只把汇总表返回模型。

边界说明，Codemode 不是 bash 沙箱替代品；高危副作用工具应声明不可安全重放。

团队：MCP 应更像带智能发现的 OpenAPI——结构化返回，而非把文本工具全倒进上下文。

接下来，第五部分，【方法/工具卡】Pi 1.0 七项「粘住墙」的更新。

核心思路：每周新概念很多，Pi 等被证明有用再权衡复杂度后收纳。

操作步骤，① 安装 curl -fsSL https://pi.dev/install.sh | sh；② 体验 Codemode+MCP、虚拟模型扩展、延迟工具加载；③ 需要长运行/多界面/多人时再评估 npm install @earendil-works/pi-durable 与 Demo。

选型条件，终端单人编码、要极简可塑 harness 时选 Pi 1.0；要 Slack 频道+线程分叉、崩溃续跑时上 Durable。

避坑，别把 Pi Durable 当已稳定生产 API——官方写明仍可能变。

落地：虚拟模型 router/auto 示例——Opus 规划、Jev 决策切换、GPT 实现；用 /session 看各模型花费与缓存命中。

接下来，第六部分，【跨概念对比表】Pi 编码 Agent vs Pi Durable。

典型用户，一人、终端、进程挂了人工续，多界面、多人、要灾难恢复，不强行把编码 Agent 撑成大平台

状态，会话为主，检查点 + requestId 恰好一次提交，分布式老概念进 Agent

工具副作用，常规 harness，replay: safe 只读可重跑，deploy 中断只告知模型，生产务实边界

代码规模，极简哲学延续，约 1.5 万行，目标让 Agent 能读框架，可跳过存储后端等模块

接下来，第七部分，【决策/选型表】Agent 运行时怎么选。

本地/远程终端写代码，Pi 1.0，官方明确专注此场景不变，为协作硬改同一包，另起 Durable 保持克制

331 次工具编排、省上下文，Codemode + MCP，脚本在 harness 侧执行，全工具塞进每轮 prompt，组合难、token 爆炸

Slack 频道与线程隔离权限，Durable 对话分叉，零拷贝分支、并发不阻塞，复制整段历史，官方频道/线程模型

需要内置权限 RBAC，外置 Gondolin/Docker/OpenShell，Pi 坦诚无内置权限，指望 harness 假安全，以启动用户权限运行

接下来，第八部分，【避坑清单卡】Pi Durable 六能力里的硬细节。

部署重复执行：未声明 replay 的 deploy 绝不会自动重放。解法：只读工具标 replay: safe。严重程度：致命。

长对话卡顿：前台总结会停对话。解法：后台压缩任务，旧消息仍留存储可检索。严重程度：小心。

供应链投毒：依赖当日新版本。解法：min-release-age、lockfile、npm ci --ignore-scripts。严重程度：致命。

社区 PR 被关：新贡献者默认自动关闭。解法：知悉维护模式再评估参与成本。严重程度：可忽略（对使用者）。

接下来，第九部分，【心法/原则卡】先验证、再收纳、保持小。

原则，特性「扔墙上看谁粘住」；终端 Agent 不够用时新包扩展，而非臃肿一体化。

为什么重要，OpenClaw 声量可起落，引擎 Pi 用克制换可依赖与可演进。

怎么落地，Durable 上试设计，有效经验反哺 Pi；Agent 读 packages/durable README 与示例上手。

适用边界，目前仅 TypeScript；Jev/Codemode 完整设计仍待后续文章。

接下来，第十部分，总结与行动。

结论

Pi 1.0 巩固「可依赖的极简编码 harness」，并以 Codemode 反转 MCP 立场，解决工具组合与上下文浪费。

Pi Durable 把检查点、幂等提交、所有权树、后台压缩系统搬进 Agent，面向长跑与多人，API 仍实验。

安全与供应链靠外置沙箱与锁定依赖，而非 harness 内假安全感。

「让 Agent 能读懂框架」是明确设计指标，影响模块划分与上手路径。

安装 Pi 1.0，用一次 Codemode 脚本完成多步 MCP 调用并对比纯对话调工具 token。

为只读与写操作工具分别设计 replay 策略，在 Durable 存储上模拟进程中断恢复。

若要多 Slack/多端协作，原型对话分叉与扩展热更新，再评估 API 稳定性风险。

生产前用 Gondolin/Docker/OpenShell 补权限边界，并核对 lockfile 与 npm audit 流程。
