接下来，第一部分，核心概念关系。

关系脉络如下：通用设置，权限/语言/Enter，然后模型层，可插拔适配器，然后插件系统，165+ 内置插件，然后Agent 预设，工具集+Prompt+编排

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「标准模式最强，所有任务都该用标准」。实际上标准模式连问候都消耗约 1 万 Token 工具定义开销；简单任务用极简、批量自动化用 PTC、定制工作流用创造，才是 Harness 的设计意图。

接下来，第三部分，反驳。

反驳

对立视角：Cursor/Copilot 重度用户 · 「预设切换太复杂，一个全能 Agent 就够了」

Harness 的插件化底座意味着「全能」= 每次推理背负 165 个插件的工具定义税——不按场景裁剪预设，省下的配置时间会在 Token 账单和响应延迟上加倍讨回来。

接下来，第四部分，【概念拆解卡】Agent 预设与环境参数集合。

在讲什么问题，预设不是换个皮肤，而是决定 Agent 加载哪些工具、用什么系统 Prompt、如何管理上下文窗口。

核心机制，四套内置模板（标准/极简/PTC/创造）封装了工具注册表、任务编排逻辑与 Cordis 插件组合的差异化配置。

关键理解，三种模式的本质差异是当前会话加载了哪些工具与配置的不同组合——标准约 20+ 工具，极简仅终端+文件编辑器两个。

典型场景，全链路开发用标准；基准测试/轻量对话用极简；批量文件操作用 PTC；沉淀团队最佳实践用创造模式生成自定义预设。

边界说明，创造模式需 Full access 权限写入全局配置；插话发送是协作式打断，窗口错过会降级为排队。

接下来，第五部分，【跨概念对比表】四种 Agent 预设横向对比。

工具数量，20+ 全套，2 个（终端+编辑器），1 个 run_code（内含全部能力），标准 + 元工具，工具越多上下文开销越大

问候 Token，~1 万，~1.2K，中等，高，简单对话别用标准

3D 游戏案例耗时，33 分钟，23 分钟（质量低），27 分钟（Token 1/3），视任务而定，速度与质量需权衡

行为风格，任务分解+多路径探索，思考-行动直连引擎，批处理代码串联工具，可自我改造预设，极简不做规划汇报

适用任务，通用开发全链路，模型跑分/简单执行，批量重命名/自动化流程，复刻 Cursor Debug 等定制流，误用预设=效率/质量双输

接下来，第六部分，【决策/选型表】权限与 Enter 键行为。

日常开发读写项目文件，Workspace Write，可读写工作区、命令需审批，安全与效率平衡，默认 Full access，可读写任意路径，误操作风险高

创造模式写全局预设，Full access，需写入 agent.cordis.yml / preset.yml，Read Only，无法生成自定义预设文件

只读审计/演示，Read Only，无法修改文件或执行命令，任何写权限，存在数据被 Agent 改写风险

Agent 忙碌时发新指令，排队发送（默认），FIFO 不打断当前回合，频繁插话发送，可能等工具调用完成才生效，急停需点终止

紧急纠正方向，插话发送，协作式打断当前回合，排队等待，错误方向可能跑完全程浪费 Token

接下来，第七部分，【方法/工具卡】创造模式定制 Debug Agent。

方法名：创造模式 + 自然语言预设生成 · 标签：团队最佳实践沉淀

核心思路：在标准能力上注入操作 Cordis 插件系统的元工具，让 Agent 读取现有预设、抓取参考文档、生成新 YAML 配置。

操作步骤，1) 模型选 DeepSeek-V4-Pro 推理 MAX ，得到 2) 权限设 Full access ，得到 3) 切换创造模式 ，得到 4) 提交提示词描述目标工作流（如复刻 Cursor Debug 模式），得到 5) 检查生成的 agent.cordis.yml 与 preset.yml ，得到 6) 新对话从模式选择器选用

原文：创造模式类似 AGENTS.md/CLAUDE.md 约束智能体，但粒度更细、自动化更高，无需手动维护结构化文档。

落地建议：插件配置可调终端超时、Agent Loop 并发工具数、网页搜索 API 凭据；企业自托管模型用 Custom Provider 填 OpenAI 兼容端点。

接下来，第八部分，【避坑清单卡】配置与预设误用。

坑名，所有任务默认标准模式导致 Token 账单爆炸

原因，20+ 工具定义每次推理都编码进系统提示词，简单问候也近 1 万 Token。

解法，按任务选预设；查看轨迹（Trace）面板审计上下文快照；PTC 批量任务可省 2/3 输入 Token。

严重程度，小心（成本）/ 可忽略（若不限预算）

插话误解：插话非抢占式强杀——若打断窗口已过会自动降级排队，需手动点终止才能立即停止。

极简模式质量：3D 游戏案例角色模型与贴图明显简化，追求视觉品质勿用极简。

插件参数：终端超时过短会误杀长构建命令；并发工具数过高可能触发下游 API 限流。

接下来，第九部分，总结与行动。

结论

通用设置五维：Agent 预设、三级权限、语言/主题、Enter 排队/插话行为。

模型层可插拔，支持 DeepSeek 官方与 OpenAI 兼容自托管端点。

165+ 插件构成 Everything is a Plugin 架构，关键参数含终端超时、并发工具数、搜索 API。

标准=全能高开销；极简=跑分/轻量；PTC=批处理提效；创造=自然语言生成自定义预设。

3D 游戏实测：标准 33min / 极简 23min（质量降） / PTC 27min（Token 约 1/3）。

日常开发保持 Workspace Write，仅在创造预设时临时升 Full access。

简单对话与模型评测切换极简模式，全链路开发用标准，批量操作用 PTC。

打开轨迹面板对比不同预设的系统提示词与 Token 消耗。

用创造模式将团队 Debug/Code Review 流程沉淀为可复用预设 YAML。
