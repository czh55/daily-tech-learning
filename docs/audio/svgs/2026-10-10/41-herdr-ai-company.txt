一句话概括。本文解决的核心问题是：如何从空文件夹搭一家「老板一句话、总经理写任务卡、经理请帮手、以文件验收」的 AI 一人公司——模型是租来的，运营体系沉淀在自有文件夹里，并用 Herdr 把 Claude Code、Codex 等 CLI 智能体拉进同一间可持久、可互发消息的办公室。

接下来，第一部分，核心概念关系。

关系脉络如下：知识库，文件夹根目录，然后办公室，Herdr 工作区，然后员工，驾驭工程+模型

接下来，第二部分，认知纠偏。

认知纠偏

误解：「Herdr 是又一个 Agent 框架」。实际是终端里的智能体复用器/办公室：后台服务持久、界面可关、员工间用官方 herdr agent 命令交接；必须在 Herdr 窗口内（HERDR_ENV=1）才能用这些协作命令。

接下来，第三部分，反驳。

反驳

对立视角：极简个人开发者 / 反流程派

为一个人写公众号搭九目录、四手册、Herdr 九条协作，维护成本已超过内容本身——直接单会话 Claude 往往更快交付。

接下来，第四部分，【概念拆解卡】员工、办公室、知识库。

在讲什么问题，一人公司最小组成是什么。

关键理解，员工 = 驾驭工程（手脚：读写文件、跑命令）+ 大模型（大脑）；办公室 = Herdr 三层（server 持久 / UI / 员工体系）；知识库 = 启动目录，空则每次失忆。

关系：员工可换租，办公室开源免费，只有知识库是你长期资产。

怎么落地，按「我是谁、我做什么…」九目录建骨架；Skill 实体只放 工具/技能/，软链到 .claude/skills 与 .agents/skills。

边界：知识库只放文字；大视频放外链并在库里记路径。

接下来，第五部分，【方法/工具卡】五段提示词流水线。

统一框架：目标+背景 ，得到【规矩】，得到【要做的 N 件事】，得到【汇报】，得到【过关标志】；先访谈复述计划、只说「可以」再动手。

过关依赖链：第一段汇报里的公司根目录完整路径是后面每段的填空项。

1 建知识库，普通终端 CLI，九目录 AGENTS.md、四岗位手册、git 首 commit

2 装 Herdr，普通终端 CLI，herdr 版本、集成、herdr Skill、权限 JSON、协作九条

3 请员工上岗，Herdr 窗口内，工作区+四页固定岗位在 角色/<名>/

4 新建岗位，Herdr 内总经理，演示 dev 开发经理

5 第一项任务，老板对总经理，SEO Skill 升级：任务卡，得到内容经理，得到tmp 查资料，得到增长审稿

接下来，第六部分，【方法/工具卡】协作规矩核心命令。

操作步骤，① 写任务卡到 驾驶舱/任务/；② herdr agent list 看状态灯（working/done/blocked/idle）；③ herdr agent prompt 带 --wait 交接；④ timeout 不重发，按规矩等；⑤ 以产出文件路径验收。

固定 vs 临时：固定岗位 herdr tab create + agent start 在 角色/<英文名>/；临时帮手 tmp- 前缀、根目录上岗、做完关页。

总经理原话：「我不亲自写长稿；改正式文件、对外发布，先停下来等老板确认。」

接下来，第七部分，【避坑清单卡】搭 Herdr 公司常见卡点。

没 git init：Codex 等从 git 根往下读 AGENTS.md，不初始化读不到总规矩——严重程度：致命。

在普通终端粘第三段：无 HERDR_ENV，herdr 协作命令不可用——严重程度：致命。

Windows 软链接失败：用 Junction 或 @AGENTS.md 一行引入，禁止复制两份内容——严重程度：小心。

说明文件过长：总规矩 ≤9000 字节、目录说明 ≤3000——上下文爆炸——严重程度：小心。

timeout 后重发 prompt：官方规矩：话多半已送到，按第 6 条等，绝不重发——严重程度：小心。

接下来，第八部分，【决策/选型表】岗位与模型分工（文内建议）。

中文长文、查资料，反重力等检索强，内容经理、tmp 帮手，与审稿同模型，看不出前稿盲点

视频脚本动效，Claude Code + 强模型，视频经理，省模型凑合，出片质量差

流量/标题审稿，与内容经理不同家，增长经理，自己审自己，视频经理规矩：换人挑稿

只有一家 CLI，全岗位同名册，仍可走通五段，放弃多模型审稿，接受质量折中

接下来，第九部分，【跨概念对比表】固定岗位 vs 临时帮手。

页面，长期一页一窗，用完关页

手册，读岗位 AGENTS.md，只读总规矩

上下文，积累工作记录，零碎任务不占主岗上下文

典型用途，管线角色，并行查资料、试模型

接下来，第十部分，【心法/原则卡】以文件为准、先计划再动手。

原则，做没做完看文件（任务卡、研究、工作记录），不靠盯屏幕；访谈复述是最便宜纠错点。

怎么落地，正式文件改前先请示老板；草稿只在 驾驶舱/任务/；有价值改动 git commit。

长期：岗位 工作记录/ 积运行数据，为以后总经理自动规划打底。

边界：目录命名是演示分法，可按自己生意改维度，但「Skill 单份实体+软链」建议保留。

接下来，第十一部分，总结与行动。

结论

一人公司 = 自有知识库 + Herdr 办公室 + 可换租的 CLI 员工。

五段提示词把建库、装 Herdr、上岗、扩岗、首任务串成可验收流水线。

协作靠任务卡 + herdr 官方命令 + 状态灯，timeout 不重发是铁律。

模型租来，运营与 Skill 沉淀在文件夹与 git 里才是护城河。
