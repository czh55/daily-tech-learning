反驳

对立视角：「只用一个全家桶」实践者

四层分类是教科书洁癖——团队只要 Claude Code 或只要 Dify 就能交付，拆 LangChain 与 Pi 是在给入门者增加选择焦虑。

接下来，第三部分，【概念拆解卡】Harness 到底是什么。

在讲什么问题，成熟产品名里常带 Harness，和 SDK 有何不同。

关键理解，Harness 是通过扩展与约束，让大模型按用户意愿决策与调工具；Claude Code 是 Anthropic 给 Claude 的实现，Codex 是 OpenAI 的，Hermes 本身即 Harness 工程。

典型场景，多数爱好者「用」智能体完成编码与文件任务，而非在其上再开发新产品。

边界：要深度定制业务流程与数据面，应下沉到 SDK 或极简扩展路线，而非硬改成熟客户端。

接下来，第四部分，【跨概念对比表】四类工具怎么选。

OpenClaw 案例：在 Pi 极简之上扩展成「巨无霸」，验证「极简 + 可扩展」路径可行。

SDK，LangChain 系，设计并搭建智能体系统，最高，学习曲线陡

极简智能体，Pi，在极小内核上扩展 Skill/MCP/UI，高，中（需写扩展）

成熟 Harness，Claude Code 等，直接当生产力工具用，低，最低

插件化 Harness，DeepSeek Harness，既用标准插件又可创设扩展，中高，中（双模式）

接下来，第五部分，【方法/工具卡】DeepSeek Harness 插件化结构。

微内核 Cordis：不实现业务，只做依赖解析、热插拔、事件与生命周期。

标准模式：官方文件/命令/搜索等插件预装，接近成熟智能体体验。

创设模式：用户开发插件扩展能力——兼顾探索期原型与后期定制。

怎么落地，先判断自己是「用」还是「造」；探索期可 DeepSeek Harness，定制度需求再评估是否下沉 Pi/SDK。

接下来，第六部分，【决策/选型表】学习路径一句话。

定制智能体系统，LangChain，只学 Claude Code 快捷键，缺构建模块视野

零开销+自研扩展，Pi，直接 fork 成熟客户端，改动面与升级成本高

日常编码助手，多款成熟 Harness 试用，强行 LangGraph 搭聊天，过度工程

用+造兼顾、原型期，DeepSeek Harness，忽视插件边界，内核与业务耦合混乱

接下来，第七部分，【避坑清单卡】选型常见误区。

把 SDK 当聊天机器人：LangChain 不负责「一个成品助手」——需自己编排——严重程度：小心。

在成熟 Harness 上硬做平台：二次开发不是主路径——严重程度：小心。

不看抽象层级跟风：OpenClaw 火就跳过 Pi 原理——扩展债难还——严重程度：可忽略（学习型）。

接下来，第八部分，总结与行动。

结论

选型本质是选抽象层级：积木、极简内核、成品 Harness、插件化 Harness。

LangChain 造系统；Pi 极简扩展；Claude Code 等直接用；DeepSeek Harness 双模式桥接用与造。

先回答「造智能体还是用智能体」，再决定学哪条线的文档与实验。

写下当前任务是产品化 Agent 还是个人效率，对应上表一行。

若「用」：并行试用 2 款成熟 Harness 一周再定主工具。

若「造」：用 LangChain 或 Pi 做最小闭环（单工具+单循环）再谈 MCP/多 Agent。

关注 DeepSeek Harness 创设模式仅在有插件需求时投入，避免过早插件化。
