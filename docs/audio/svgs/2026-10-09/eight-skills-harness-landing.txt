一句话概括。本文解决的核心问题是：架构图之外，八个 Skill 如何被业务「逼」出来、三条内部设计如何保证企业场景稳定运行、四个月量化效果如何——以及当工具名会过时，「拆框架看环节 + 可验证约束」为何比记住 Spec Kit 阶段数更持久。

接下来，第一部分，核心概念关系。

关系脉络如下：product，然后api，然后ui，然后page，然后test，然后qa，然后review

接下来，第二部分，认知纠偏。

认知纠偏

误解：「八个 Skill 是一次设计好的成品」。作者：从 product/page/review 三个起步，qa、bugfix 等是被返工与线上问题逼出来的；每 3–4 个需求还要微调决策点。

接下来，第三部分，反驳。

反驳

对立视角：裸 Copilot 效率派

2 天交付还搭八 Skill、80 行宪法，是把 AI 又套回瀑布——小改动能秒级生成时，流程是在为流程付费。

接下来，第四部分，【方法/工具卡】八个 Skill 职责速查。

product，六维评审、任务拆解，grill-me：一次一问，PRD×代码交叉审

api / ui / page，类型与请求、组件、四态页面，ui 强制封装组件；page 覆盖加载/空/错/正常

test / qa，行为基线、提测前扫 Excel 用例，qa 对照 product.md 验收标准

review，CR + 规范回写 CLAUDE.md，与框架自带 review 不同：可回流宪法

bugfix，根因，得到范围，得到验证，根因说不清不许动手

接下来，第五部分，【概念拆解卡】三条共同设计（比步骤更重要）。

设计一：每个 Skill 开头必须先读 CLAUDE.md——否则 ui 会满屏 antd 原生，违背 L1 封装。

设计二：明确决策点，不确定就停（[待确认]）——企业场景全自动是灾难。

设计三：末尾「常见坑速查表」三列（现象/原因/处理），review 交付后持续追加——灵感来自 Superpowers Red Flags，堵 LLM 自我合理化。

AI 不知道的事不会主动问——不喂约束，它就按训练数据里的通用实践来。

接下来，第六部分，【跨概念对比表】四个月量化 vs Superpowers 全链。

中等需求交付，评审，得到review 约 2 天，纯手工约 2× 时长

PR 轮次，1–2 轮（原 2–3），review 首轮拦约 70% 低级问题

Token，按需调用 Skill，约为 Superpowers 全链 1/4–1/3

CLAUDE.md，20 行，得到80 行，每条来自 review 真实漏洞

spec 复用，20+ 需求归档，新需求约 30% 可复用

接下来，第七部分，【避坑清单卡】何时别上八 Skill。

极致 TDD / 小团队 hotfix：Superpowers 14 Skill 或裸 Claude Code 更划算——流程固定成本大于收益。

把建议写进 CLAUDE.md：「好好写代码」无效——改成可 review 的必须/禁止——严重程度：致命。

期待装完就不用管：活系统，每几条需求就要调决策点——严重程度：小心。

接下来，第八部分，【决策/选型表】立刻能做的三件事。

单目录收产出，spec/changes/<feature>/，八个 Skill、Delta、三层架构

宪法可验证，删模糊建议，写一条硬约束，完整组件分层表

一个最痛 Skill，触发条件+步骤+坑表，八个全写

接下来，第九部分，【心法/原则卡】工具会过时，方法不会。

架构变强制项：AI 以同样速度复制烂模式——组件分层表是架构约束的可执行版。

执行占比下降、判断占比上升：AI 卷低敲键盘门槛，卷高「该不该用 hooks」这类判断天花板。

拆工具三问：做什么 / 怎么做 / 按什么标准——明年第四个框架仍可用。

胶水成本：工具之间的缝靠人手填——缝越多人越累。

接下来，第十部分，总结与行动。

结论

Skill 数量与内容是跑出来的，三条内部设计（读宪法、决策点、坑表）是稳定运行的底座。

四个月数据说明速度与纪律可兼得，但 TDD 铁律深度仍不及 Superpowers。

文章数字是 2026-07 快照，相对差异比绝对分钟数更值得记住。

选型前先问：要解决流程哪一环——量身定做比万能钥匙可靠。
