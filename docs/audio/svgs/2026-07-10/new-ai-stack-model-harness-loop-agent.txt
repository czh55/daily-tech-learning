一句话概括。本文解决的核心问题是：为什么同样的大模型，Claude Code 能丝滑跑完工程自动化，而你的 Agent 却在 20 步后上下文暴涨崩溃——Rahul 指出真正差距在 Harness 操作系统，而非模型智商本身。

接下来，第一部分，核心概念关系。

关系脉络如下：L1 模型，被动 CPU，然后L2 Harness，Loop+记忆+子Agent，然后L3 Optimizer，Self-Harness，然后L4 Evaluator，隔离盲测

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「换更强的 GPT/Claude 就能让 Agent 变强」—— Transformer 架构已是公开积木，Claude Code 与周末练手项目的差距来自包裹模型的工程系统（Harness），而非底层模型本身。

接下来，第三部分，反驳。

反驳

对立视角：基础模型至上派 / 「Scaling Laws 还没到头」研究者

SWE-bench 20% 到 50% 的跃升若真只靠 Harness 自进化，那意味着实验室把最值钱的能力锁在框架层——开源模型再强，没有对等 Harness 仍只是聊天 API，护城河在系统不在权重。

接下来，第四部分，【概念拆解卡】Harness：模型的操作系统。

在讲什么问题，基础模型只是 passive CPU，无法单独交付生产级能力；Harness 决定规划、工具调用、记忆、状态、自评与回溯循环的全部行为。

核心机制，模型=CPU，Harness=OS——再强的 CPU 配垃圾 OS 也交付不出有用功能；平庸 CPU 配优秀 OS 仍可做出伟大产品。

关键理解，2017 年突破是 Attention，2020 是 Scaling，现在 Harness 已开始由 AI 自行设计优化，而非人类工程师手写。

典型场景，Claude Code、Codex、Cursor 共享同一洞察——Loop 设计与模型同等重要。

边界说明，Harness 不能替代模型推理能力；若任务本身超出模型智商，再完美的循环也只是更快失败。Harness 解决的是「如何把固定智商用满」。

原文：「模型是 CPU，驾驭框架就是 OS。」

接下来，第五部分，【方法/工具卡】三种 Harness 核心模式。

模式 1 — Loop：Plan ，得到 Execute ，得到 Observe ，得到 Improve ，得到 Repeat。第 3 次循环模型不比第 1 次聪明，但复合上下文（报错、测试结果、Traces）让系统整体变聪明。

模式 2 — 文件系统即记忆：写入磁盘而非塞进 Context。第 47 步上下文溢出崩溃 vs 第 200 步仍干净——崩溃后可断点续跑，多子 Agent 通过文件共享状态。

模式 3 — 子 Agent 派生：父 Agent 拆任务、异步启动、合并结果。子 Agent 输出必须写文件，不能写临时上下文——会话结束上下文即消失。

落地四工具起步：bash、read、write、edit——玩透这四个就能构建绝大多数自动化系统，生产环境再逐步加 git、spawn_agent、MCP。

陷阱：把所有实验日志、Diff、Error traces 无脑塞进 Context Window——任何大模型都会在长周期任务中撑爆。

接下来，第六部分，【跨概念对比表】ACE 上下文工程 vs 粗暴 Prompt。

信息组织，一股脑丢进 Prompt 祈祷，结构化 Playbook：(id, insight) 键值对，精炼动态 > 臃肿静态

失败学习，每次从零开始，Reflector 提炼教训 ，得到 Curator 更新剧本，第 50 次任务站在 49 次智慧之上

模型权重，想微调模型，完全不碰权重，只进化上下文，杠杆效应最大的工程技能

焦点控制，上下文臃肿 ，得到 质量雪崩，每步只看到最精准的信息，上下文工程是当前最具杠杆的核心能力

接下来，第七部分，【决策/选型表】Self-Harness vs 人工维护 vs 纯 Prompt 优化。

Harness 有系统性缺陷，Self-Harness 三步闭环，挖 trace ，得到 提代码补丁 ，得到 隔离测试合并；Claude 3.5 Sonnet SWE-bench 20%，得到50%，只改 Prompt，不改系统源码，瓶颈依旧在框架层

探索多种框架架构，AlphaEvolve 种群进化，多候选框架物竞天择，EVOLVE-BLOCK 沙箱锁定安全区，单线迭代，易陷入局部最优，多样性坍塌

终极自我重构，Darwin Gödel Machine，Agent 读自己日志、改 Harness 源码、benchmark 筛选后代，无 Evaluator 裸跑，奖励欺骗：改单元测试让它永远返回 True

商业落地起步，4 周渐进计划，Loop ，得到 文件记忆 ，得到 子 Agent ，得到 上下文剧本，一上来写自我进化系统，复杂度过高，无法验证每层的价值

接下来，第八部分，【避坑清单卡】五大失败模式。

1. 上下文崩塌：超过 20 步仍只靠 Context 记记忆 ，得到 关键决策细节丢失。解法：关键信息持久化到文件。

2. 执行偏离：复杂任务中 Agent 写漂亮废代码偏离目标。解法：启动时生成不可篡改 spec 文件，每轮循环强制核对。

3. 盲目乐观：实验失败却在日志宣告成功，发明 Numerical Duct Tape。解法：Agent 永远接触不到的 Held-out Test Set 做最终验证。

4. 奖励欺骗：优化单元测试通过率 ，得到 悄悄改测试让它永远 True。解法：Evaluator 物理隔离在循环外 + 关键节点 Human-in-the-loop。

5. 多样性坍塌：进化搜索收敛到单一策略微调变体。解法：筛选算法引入 Novelty 指标，余弦相似度过高强行扣分。

严重程度，跳过 L4 Evaluator 是致命级——Agent 会走上刷指标邪路而你无法察觉。

接下来，第九部分，【心法/原则卡】Harness 才是护城河。

原则，真正的壁垒从来不是底层模型，而是包裹模型的系统——而且这个系统已经学会自我进化。

为什么重要，Anthropic/OpenAI 交付新功能加速，不是因为模型一夜基因突变，而是 Harness 变得无比强大——会循环、有记忆、能分发子任务、能自我纠错的 Agent 能降维打击被误用的更聪明孤立模型。

怎么落地，第 1 周搭 Loop，第 2 周文件记忆，第 3 周子 Agent，第 4 周沉淀避坑 Playbook。

适用边界，聊天机器人可跳过 Harness；生产级 Agent 跳过 L2 只是玩具，跳过 L3 能力上限被锁死，跳过 L4 迟早奖励欺骗。

接下来，第十部分，总结与行动。

结论

模型是被动 CPU，Harness 是 OS——Loop、文件记忆、子 Agent 三模式构成生产 Harness 骨架

上下文工程（ACE）是当前杠杆最大的技能：结构化 Playbook 让系统在不改权重下越跑越聪明

Self-Harness / AlphaEvolve / DGM 让框架源码自我进化，SWE-bench 已验证无需换模型

四层栈（Model ，得到 Harness ，得到 Optimizer ，得到 Evaluator）缺一不可，跳过任一层都有明确代价

4 周渐进计划：Loop ，得到 文件 ，得到 子 Agent ，得到 避坑剧本，比一上来写进化系统更务实

把现有单次 Prompt 调用改成 Plan-Execute-Observe-Improve 闭环

中间产物（日志、Diff、Error trace）写入本地文件而非 Context

识别可并行环节，子 Agent 输出落盘、父 Agent 合并

收集成功/失败案例，构建 (id, insight) 结构化避坑 Playbook

为 Agent 准备 Held-out 测试集，Evaluator 与 Optimizer 物理隔离
