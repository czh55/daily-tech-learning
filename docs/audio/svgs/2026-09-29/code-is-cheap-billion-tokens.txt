一句话概括。本文解决的核心问题是：「Code is cheap」是否成立——作者用百亿级 Token 与 SDD 落地经验说明，AI 对烂代码容忍度更低、乱码指数会指数传染；百万上下文只有前段可靠，反馈闭环是导航而非加分项，深模块由人定边界、AI 填实现。

接下来，第一部分，核心概念关系。

关系脉络如下：干净样本，库基准，然后AI 生成，然后烂模式，传染，然后Lint/测试，防火墙

接下来，第二部分，认知纠偏。

认知纠偏

误解：「不会写代码也没关系，AI 能补」。原文指出代码库真实现状比 CLAUDE.md 规范更有影响力——五十个违规接口会让模型优先模仿违规模式。

接下来，第三部分，反驳。

反驳

对立视角：「Code is cheap」效率派

在原型验证与一次性脚本场景，先堆出能跑的代码再重构，比死守深模块和分层测试更快拿到业务反馈——质量投资应跟在产品已验证的需求后面。

接下来，第四部分，【概念拆解卡】乱码指数与死亡螺旋。

在讲什么问题，AI 提高提交频率，却不自动提升架构与测试质量，库倾向更快腐化。

核心机制，乱码指数低时 AI 还能找到干净参考；超过约六成劣质样本淹没优质模式，输出更差实现，螺旋上升。

关键理解，人靠长期记忆绕坑；新会话 AI 只能从仓库归纳，烂代码会指数级传染。

典型场景，文档写满规范，现存接口却无一遵守——模型照搬接口而非文档。

边界说明，架构缺陷可能数月后才暴露，单会话看不见三年业务演进，委托 AI 做架构要问回滚成本。

接下来，第五部分，【概念拆解卡】上下文窗口的有效区。

在讲什么问题，百万 Token 看似能装下全库，可靠推理区仍有限。

核心机制，靠前约六成内容判断稳定；越往后幻觉、遗忘约束越明显。LLM 非确定性，上周过的测试下周可能挂。

关键理解，compact 压缩层层损信息；任务拆解 + 短会话优于硬撑长上下文。

典型场景，独立干净会话完成子任务后结束，而非一条线程堆满全项目。

边界说明，窗口变大不取消「前段清醒区」规律，只改变能塞多少噪声。

接下来，第六部分，【方法/工具卡】分层反馈导航系统。

核心思路：AI 无人类脑内业务地图，缺闭环等于闭眼开车。

操作步骤，① 改文件后 10 秒内跑类型检查/Lint；② 两分钟内跑模块单测；③ 提交前全量测试；④ 能写进 Lint 的规则不要写进 Prompt（成功时零 Token）；⑤ 编码 Agent 与审查 Agent 分上下文，规范只给审查方。

选型条件，TypeScript 等强类型近乎零延迟纠偏；弱类型需更靠测试兜底。

避坑，漏到第三层才发现的错误，可能已基于错误假设写满文件，推翻成本远高于第一层拦截。

铁律：能自动化校验的约束放进 Lint/pre-commit，省下的上下文留给业务与架构判断。

接下来，第七部分，【方法/工具卡】深模块与灰盒协作。

核心思路：薄接口、厚实现（Ousterhout 深模块），对外只暴露 SDK 与 API Handler，复杂度内聚。

操作步骤，① 人识别纠缠子系统（多文件跨前后端 CLI）；② 收敛对外导出；③ AI 在接口下填实现；④ 用端到端集成测试定位故障。

对比相邻方法，浅模块大量导出，AI 错一个返回值可污染全链；深模块错误被薄接口阻断。

避坑，「该封成深模块」的判断现阶段 AI 做不好，需人跨层抽象。

接下来，第八部分，【跨概念对比表】人类编码 vs AI 编码。

全局业务图，可一小时不写测试仍方向对，每行概率采样，无距离感，AI 更依赖即时反馈

历史烂坑，长期记忆绕过，新会话从库归纳，库质量是上限

架构决策，可权衡多年演进，单会话难见全局，人选可回滚方案

自我审查，能中途察觉跑偏，偏爱自己刚写的代码，独立审查 Agent

接下来，第九部分，【避坑清单卡】AI 编码急性风险。

规范文档幻觉：以为写了 CLAUDE.md 就能约束输出。原因：库样本权重更大。解法：先清理基准接口与模式。严重程度：致命。

长会话依赖 compact：压缩噪声累积。原因：信息损耗不可预测。解法：拆任务、新会话。严重程度：小心。

Prompt 堆规则：占用全程 Token。原因：Lint 成功时不消耗。解法：规则下沉工具链。严重程度：小心。

浅模块 + 高自治：错误沿依赖扩散。原因：接口过宽。解法：人收敛边界。严重程度：致命。

接下来，第十部分，【心法/原则卡】人管接口，AI 管实现。

原则，代码不廉价——烂代码在 AI 时代从慢性病变急性隐患。

为什么重要，腐化、深模块、反馈闭环都是老话题，新变量是提交频率与模仿速度。

怎么落地，Red-Green-Refactor；委托设计前问回滚成本；平铺与低耦合优先于炫技嵌套。

适用边界，审查与架构判断永不过时，AI 是强实习生而非架构师。

接下来，第十一部分，总结与行动。

结论

AI 放大提交频率，也放大库腐化速度；烂模式会指数传染。

百万上下文可信区仍在会话前段，compact 不如拆任务。

分层 Lint/单测/全量是 AI 的导航系统，不是可选项。

规则进 Lint 不进 Prompt；编码与审查应分 Agent。

深模块由人定界，控制 AI 写错时的爆炸半径。

抽样审计现存 API/模块，对齐团队规范，降低乱码指数。

为常用栈配置保存后 10 秒内触发的 Lint/typecheck。

下一次让 AI 做设计前写下回滚方案与最差情况成本。

选一个纠缠子系统试点深模块封装与集成测试。

建立独立审查流程，规范文档只注入审查上下文。
