一句话概括。本文解决的核心问题是：当 ReAct 循环、工具注册表、上下文压缩等 Harness 约定都是人工写死时，Coding Agent 能否把每次编码交互中的可执行反馈（单测、编译诊断、CI 日志）转化为对未来行为的持久改动——南京大学综述《Self-Evolving Coding Agents》用五维分类、三种时机、三类证据给出了一张可对照的工程地图。

接下来，第一部分，核心概念关系。

关系脉络如下：五维进化对象，框架·记忆·技能，模型·工作流，然后三种时机，任务内·任务后，阶段性，然后三类证据，结果·环境，轨迹衍生，然后持久资产，跨任务复用，而非单次修补

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「给 Agent 加记忆模块 = 自进化」。仅当软件工程经验被反馈进决定未来行为的组件（记忆策略、技能库、工作流拓扑甚至脚手架代码），且改动可跨任务持久，才算自进化 Coding Agent——单纯把对话历史存起来不算。

接下来，第三部分，反驳。

反驳

对立视角：务实 Harness 工程师 / 「先把静态版跑稳」派

框架自进化与动态工作流搜索的验证、回滚和 Token 开销远超多数团队承受力——在静态 Harness 尚未稳定通过 SWE-bench 之前，追逐自进化更像用复杂性掩盖基础工程债。

接下来，第四部分，【概念拆解卡】自进化 Coding Agent：与普通 Coding Agent 的边界。

在讲什么问题，「Coding Agent」「通用自进化 Agent」「自进化 Coding Agent」三个概念常被混用，论文先划清边界再谈技术。

核心机制，Coding Agent 在 SWE 环境里行动但部署后模型/提示词/工具/记忆基本固定；通用自进化 Agent 跨场景改提示词/记忆/策略；二者交集的关键差异是反馈来源——仓库、单测、CI、编译诊断等可执行软件制品，比纯文本评价更具体也更易过拟合某仓库。

关键理解，普通 Agent 用反馈修补当前 Bug；自进化 Agent 把反馈攒成能穿越到下一任务的资产（记忆、技能、工作流、甚至脚手架本身）。

典型场景，同一仓库反复修相似 Issue 时，应从历史轨迹提炼定位策略而非每次从零探索。

边界说明，面向 SWE 数据的后训练（如 SWE-RL）若未闭环在 Agent 自身演化尝试上，更准确定位是「模型优化」而非严格自进化。

「普通 Coding Agent 只是在『用』反馈修补当前这个 Bug，自进化 Coding Agent 是在『攒』反馈，把它变成能穿越到下一个任务的资产。」

相关概念：Reflexion / ExpeL 属于通用自进化；SWE-agent / OpenHands 属于固定 Harness 的 Coding Agent。

接下来，第五部分，【跨概念对比表】五维进化对象：改什么、风险在哪。

框架自进化，SICA、Darwin Gödel Machine，Agent 实现代码、提示词方案，有害修改可搞垮整个循环或钻评测空子，最激进，需验证+回滚+鲁棒性检查

记忆自进化，SWE-Exp、Repository Memory，经验库、仓库时间结构摘要，噪声日志/脆弱补丁生成「坏记忆」，关键在「存得对」而非「存得多」

技能与工具，CODESKILL、Live-SWE-Agent，任务级技能、动态创建编辑器/搜索工具，技能过度仓库特化，记录「下次该怎么做」而非「发生了什么」

模型自进化，Self-play SWE-RL、Agent-RLVR，策略、奖励模型、验证器，训练信号未真正闭环则只是后训练，环境从评测工具变为学习闭环一部分

工作流拓扑，EvoMAC、AgentConductor，角色分工、通信 DAG，过拟合基准、协调开销膨胀，从「人工划定何时委派」到「系统自己学会」

接下来，第六部分，【方法/工具卡】三种进化时机 × 三类证据：正交坐标轴。

核心思路：分类法回答「改什么」，时机与证据两条轴回答「什么时候改、靠什么改」。

操作步骤，① 判定当前需求是任务内即时纠偏（测试失败即调策略）还是任务后沉淀（轨迹，得到记忆/技能）还是阶段性跨代更新（大批轨迹后改模型/变体档案）；② 为每档选择证据类型——结果证据选优、环境反馈定位卡点、轨迹衍生证据抽象经验；③ 三者组成证据供应链，非互相替代。

选型条件，任务内，得到Live-SWE-Agent 在线建工具、SEMAG 动态协作；任务后，得到SWE-Exp/CODESKILL/GSkill；阶段性，得到Darwin Gödel Machine、Self-play SWE-RL。

「结果证据擅长『选优』，环境反馈擅长『即时纠偏』，轨迹衍生证据擅长『沉淀经验』。」

落地：Hand-rolled Harness 的 Context Compaction 解决「装不下」（任务内压缩）；Repository Memory / SWE-Exp 解决「不用重新学」（任务后持久记忆）——二者互补而非替代。

避坑：结果证据擅长选优但粗粒度；单靠 pass rate 看不出提升来自记忆还是工作流还是模型——评测需暴露进化过程本身。

接下来，第七部分，【决策/选型表】Harness 工程决策：从「感觉需要」到「按图索骥」。

上下文窗口不够，任务内 Compaction + 任务后 Repository Memory，压缩丢信息 vs 提炼跨会话资产互补，只靠无限拉长 Context，装不下时仍会丢关键轨迹

重复性命令/测试失败，CODESKILL 事件驱动技能库，从失败轨迹自动挖掘应对策略，人工穷举 Error Recovery 模板，静态规则库无法覆盖新模式

复杂 Issue 需多角色协作，AgentConductor / SEMAG 动态拓扑，简单任务少协作、难任务才拉起密集 DAG，固定 Subagent 委派规则，无法按任务难度伸缩协作开销

评测会自我修改的 Agent，追踪变体档案 + 报告 Token/检索开销，防基准过拟合与「钻空子」，只看单次 pass rate，筛选机制本身可能被过拟合

允许 Agent 改自己代码，验证+回滚+拦截「高危自我修改」，误导性反馈影响未来所有行为，仅拦截 bash 高危命令，Middleware 需覆盖脚手架级修改

接下来，第八部分，【避坑清单卡】综述泼的四大冷水。

坑 1：可复现性与基准过拟合——Agent 随运行/仓库/模型版本变化，用基准选自我修改对泄露和噪声极敏感。解法：维护可比较变体档案、跨仓库泛化测试。严重程度：致命。

坑 2：反馈可靠性与工具依赖——测试、CI、学习出的奖励模型都不完美；改工具/工作流时一次误导反馈污染未来所有行为。解法：审计进化过程、约束可修改范围。严重程度：致命。

坑 3：记忆腐化与多智能体协调——经验库陈旧、失败轨迹污染、协作拓扑成本膨胀。解法：记忆检索前做质量过滤、定期淘汰。严重程度：小心。

坑 4：评测短视——pass rate 不反映可维护性/安全性/长期可靠性。解法：单独报告效率开销与跨场景迁移。严重程度：小心。

接下来，第九部分，【心法/原则卡】手工 Harness 是边界，自进化是下一步。

原则，ReAct、工具注册表、Context Compaction、错误自愈等手工实践先趟出 framework/memory/skill 的进化对象边界；自进化研究要在边界清晰后，把「何时改、靠什么改、怎么验证」系统化。

为什么重要，专栏讨论「怎么把 Harness 做对」，综述讨论「做对之后怎么自己变得更对」——二者是递进关系而非替代。

怎么落地，① 对照五维分类评估现有模块属于哪类进化对象；② 为每类选定时机档位与证据类型；③ 评测脚本除测版本好坏，还要测筛选自我修改是否过拟合。

适用边界，方向仍年轻，进化过程本身需可验证、可审计、可约束——「学会进化」不等于「可信进化」。

「这不代表专栏里的工程实践过时了——恰恰相反，进化对象的边界正是靠手工 Harness 先趟出来的。」

接下来，第十部分，总结与行动。

结论与行动

自进化 Coding Agent 的核心是把可执行 SWE 反馈转化为跨任务持久改动，而非单次 Bug 修补。

五维分类（框架/记忆/技能/模型/工作流）+ 三种时机 + 三类证据构成完整坐标系。

手工 Context Compaction 与记忆自进化互补：前者解「装不下」，后者解「不用重新学」。

评测自进化系统需暴露进化过程、报告开销、测跨仓库泛化——光看 pass rate 不够。

四大挑战（可复现、反馈可靠性、记忆腐化、评测短视）决定方向能否走向可信。

阅读综述原文（arXiv:2608.03392）与 Awesome 仓库，按五维对照现有 Harness 模块。

若已有错误恢复模板，评估能否升级为 CODESKILL 式事件驱动技能自动挖掘。

在 Benchmark 脚本中增加变体追踪与 Token/检索开销字段，防自我修改过拟合。

为 Middleware 增加「高危自我修改」拦截规则，覆盖脚手架/工具级变更。

任务结束后试点 Repository Memory：把成功/失败轨迹提炼为可检索经验而非仅压缩丢弃。
