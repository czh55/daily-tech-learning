一句话概括。本文解决的核心问题是：AI 放大的是软件工程老毛病而非取代架构师——在「没对齐、太啰嗦、跑不起来、泥球化」四类失败模式中，为何第四条不可逆，以及为何约束 AI 输出的优先级是代码库形态大于 skills 大于 CLAUDE.md。

接下来，第一部分，核心概念关系。

关系脉络如下：对齐/啰嗦，可补救，然后跑不起来，加测试，然后泥球，不可逆，然后深度模块，藏复杂度，然后渐进披露，AI 只读所需

接下来，第二部分，认知纠偏。

认知纠偏

误解：AI 会写代码了架构师就失业。作者认为 AI coding 本质是软件工程与项目管理；Matt Pocock 的 skills 骨架是在复习基本功，不是教工具快捷键。

接下来，第三部分，反驳。

反驳

对立视角：「提示词工程足够，不必动架构」派

当 AI 每轮全库复读，再精的 CLAUDE.md 也打不过它亲眼看到的泥球——你优化的是台词，它学的是布景。

接下来，第四部分，【概念拆解卡】四种 Agent 失败模式。

在讲什么问题，skills 仓库 README 里「Why These Skills Exist」四条坑与经典工程问题的对应。

关键理解，没做要的=需求澄清；太啰嗦=领域语言；跑不起来=反馈闭环；泥球=深度模块与持续重构。前三可事后补，泥球一旦成型后续都在泥上改。

怎么落地用：本篇聚焦第四条——先治架构与模块深度，对齐与提示词留到下篇。

原文依据，AI 加快写代码也加快软件熵增长，变乱速度前所未有。

接下来，第五部分，【心法/原则卡】代码库 > skills > CLAUDE.md。

原则，影响 AI 输出的排序：代码库形态第一，skills 第二，项目说明第三——talk is cheap, show me code 对 AI 同样成立。

为什么重要，AI 每次从零读库、无品味地复制烂模式；CLAUDE.md 写「别这么写」仍可能照抄库里的写法。

怎么落地，投资可维护结构；写清 commit message（改了什么+为什么），给下一会话的 AI 当「生长史」。

边界说明，人靠记忆能忍烂代码；AI 没有这种耐受度。

接下来，第六部分，【概念拆解卡】好架构三句话（Ousterhout）。

改得动：单次改动影响面小，变更放大低。

读得懂：认知负荷低，少「未知的未知」。

边界清楚：复杂度压在深模块里，接口薄，决策不外泄。

怎么验证：挑最近改过的模块——波及几个文件？有没有不敢动的地方？十分钟内可验，与设计模式数量无关。

接下来，第七部分，【方法/工具卡】深度模块与「删模块」检验。

核心思路：大量行为藏在小接口后（灰盒，出事可往里看）；深度是接口属性不是实现属性。

操作步骤，1）想象删掉模块 ，得到 2）若只换调用名=浅转发，可删 ，得到 3）若复杂度散落各调用方=深模块，复杂度被收住 ，得到 4）人管接口，AI 可重写实现只要接口与测试不变。

避坑，只有一个实现就别为「以后换数据库」先垫接口——等第二种实现出现再切。

测试写不下去：不是「代码不好测」，是架构没留接缝（seam），应重划边界而非硬补测试。

课程示例：改前 load ，得到 materialize ，得到 update 三步自己记；改后 courseManager.publish(lessonId) 单入口。

接下来，第八部分，【方法/工具卡】渐进式披露三级梯。

第一级：步骤——怎么做直接摆出来（对外三个函数）。

第二级：同层参考——实现细节在旁边（源代码）。

第三级：外部参考——少数情况才要（设计说明、单测失败才翻）。

选型：分不清放前还是放后时先放前——放前最多多读一段，放后可能永远读不到。

接下来，第九部分，【跨概念对比表】浅模块 vs 深度模块。

理解成本，开五个文件才懂一概念，单入口 + 可选下钻，浅=上下文爆炸

Bug 位置，边界散落多文件，接口端到端可测，深=几分钟定位

实现替换，调用方牵连大，实现可整删重写，深=适合 AI 填实现

接口层数，为假想变化多一层，有第二实现再加，少无效转发

接下来，第十部分，【避坑清单卡】在泥球上堆 skills 和提示词。

坑名，库已是二十文件互 import，却指望 CLAUDE.md 约束 AI 不乱抄。

原因，模型权重向现有模式；约束文档弱于结构示范。

解法，先收口深模块与披露层级，再配 skills；commit 写清「为什么」。

严重程度，对长期 AI 协作：致命。

接下来，第十一部分，总结与行动。

结论

AI coding 放大的是对齐、反馈、可维护性等经典工程问题。

「建出泥球」不可逆，应优先于前三类可补救失败。

约束 AI 的首要杠杆是代码库架构，而非提示词 alone。

深度模块收复杂度，渐进式披露控制 AI 阅读路径。

commit message 成为 AI 读者理解「为什么」的关键文献。

选一个最近难改的模块，做「删掉它」检验判断深浅。

把多步业务流程收成单一对外入口，复杂度下沉。

为对外 API 写行为测试，把测试当接口契约主文档。

下三次 commit 强制写清动机，而不仅是 diff 摘要。

阅读 mattpocock/skills 的 CONTEXT 思路，准备下篇对齐与闭环。
