一句话概括。本文解决的核心问题是：采集到的异构原始语料（论文 PDF、社区文章、漏洞 JSON 等）如何经过 MinerU 解析、多模态图片描述、去重、质量过滤、隐私脱敏五道工序，炼成可直接用于大模型预训练的干净 Markdown 数据集。

接下来，第一部分，核心概念关系。

关系脉络如下：异构原料，PDF/docx/网页，然后MinerU 解析，统一 Markdown，然后Qwen-VL，图片描述，然后去重，然后质量过滤，然后隐私脱敏，可用语料

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「OCR 转成 Markdown 就能直接训练」。实际上社区爬取数据混着转载重复、广告导流、真实 IP 和邮箱；论文中的攻击链图、拓扑截图若不做多模态描述，纯文本模型会丢失关键知识；跳过脱敏还可能让模型在回答中「背出」受害单位资产信息。

接下来，第三部分，反驳。

反驳

对立视角：数据规模至上派 · 「先训再说」倡导者

五道工序下来八成语料被滤掉、图片描述还要人工抽检——治理成本远超训练本身，对小团队而言直接买现成清洗数据集更划算。

接下来，第四部分，【概念拆解卡】预训练数据治理流水线。

在讲什么问题，数据采集只是第一步，形态各异的「原料」无法直接喂给模型，必须搭建完整加工流水线。

核心机制，先用文档解析工具统一转 Markdown（保留标题层级便于分块），再经去重、质量过滤、隐私脱敏三道清洗，最后按需分块导出。

关键理解，Markdown 是理想中间格式——章节语义可指导后续切分与清洗；图片信息需通过多模态模型「翻译」为文本才能被纯语言模型消化。

典型场景，网络安全垂直大模型、领域预训练、企业私有语料库建设。

边界说明，流水线解决的是通用预训练语料治理；指令微调/SFT 格式转换是下一篇文章（LLaMAFactory 增量预训练）的范畴。

原文：「如何将这些纷繁复杂的原始素材，转化为标准、干净的预训练数据集呢？答案在于搭建一条完整的数据加工流水线。」

接下来，第五部分，【方法/工具卡】MinerU 解析 + Qwen-VL 图片描述。

方法名：MinerU + qwen3.8-flash 多模态描述 · 标签：文档解析 / 图文转文本

核心思路：MinerU 将 PDF/docx 统一解析为 Markdown（公式转 LaTeX、双栏论文阅读顺序正确）；对 images/ 目录中的图片批量调用多模态模型生成描述，用【图片内容：...】替换原始 ![](images/xxx.jpg) 引用。

操作步骤，1) conda create -n mineru && pip install -U "mineru[all]" ，得到 2) mineru -p ./raw_docs -o ./raw_output（GPU 有限加 -b pipeline），得到 3) 正则提取 Markdown 图片引用 ，得到 4) base64 编码调用 qwen3.8-flash 生成描述 ，得到 5) 批量替换并写回 .md 文件

落地建议：GPU 资源紧张时用 pipeline 模式；批量图片描述加 0.5s 限速避免 API 限流；生成后按 5%~10% 抽检图文一致性。

避坑：多模态模型会「看图说话说过头」编造图中不存在的细节——关键报告（如威胁分析攻击链图）需全量人工复核，宁可少几张图描述也不让错误信息混入训练集。

接下来，第六部分，【跨概念对比表】精确去重 vs 近似去重。

适用场景，原样复制的转载，改标题、换导语的洗稿，两级策略互补

速度，极快，哈希判定，线性时间复杂度，先精确再近似

核心工具，hashlib.md5，jieba + datasketch，工业级实用组合

关键参数，无，num_perm=128, threshold=0.7~0.9，小样本先调参

传递性重复，不适用，需并查集合并关联项，LSH 召回后二次 jaccard 验证

接下来，第七部分，【决策/选型表】三道清洗工序的工具选择。

去重，MD5 精确 + MinHash LSH 近似，覆盖原样复制与洗稿两类转载，仅 MD5，改几个字就失效

质量过滤，规则过滤为主，模型二次判断存疑项，规则快且零成本，模型慢且贵，全量模型过滤，速度慢、成本高

隐私脱敏，正则基础脱敏 + 模型识别叙述句实体，IP/邮箱/口令正则覆盖广，人名账号需模型，仅正则，漏掉「运维账号 admin_zhang」类叙述

文档解析，MinerU（学术论文/固定版式 PDF），公式表格还原出色，支持 CPU pipeline，手工复制粘贴，无法规模化

接下来，第八部分，【避坑清单卡】数据治理常见陷阱。

坑名，多模态图片描述不做一致性检验

原因，模型会编造图中不存在的细节，错误描述进入训练集后难以追溯。

解法，批量生成后 5%~10% 抽检；关键报告全量人工过一遍。

严重程度，致命（污染训练集）

跳过隐私脱敏：安全文章含真实 IP、邮箱、内网主机名，模型可能在回答中泄露敏感内容。

模型过度脱敏：脱敏时误伤 CVE 编号、版本号等技术信息——prompt 中明确保留非敏感技术术语。

质量过滤太松：社区数据混着广告、导航栏残留——宁可错杀少量低质文本，也不让噪声进入训练集。

接下来，第九部分，【心法/原则卡】宁可错杀也不放过噪声。

原则，质量过滤的目标是「宁可错杀少量低质文本，也不让噪声进入训练集」；脱敏后按 5%~10% 抽检确认无漏网之鱼且无过度脱敏。

为什么重要，同一漏洞通告被十几个网站转载，不去重会挤占学习配额并过拟合高频重复文本；低质广告和敏感实体则直接损害模型可用性与合规性。

怎么落地，规则过滤（有效字数、特殊字符占比、广告关键词）覆盖明显噪声；存疑文本才调用 qwen-plus 做 0/1 判断；脱敏分正则 + 模型两段式。

适用边界，适用于领域预训练语料治理；通用互联网大规模爬取可在此基础上扩展上百条规则。

原文：「经过以上三道工序——去重、质量过滤、隐私脱敏，Markdown 文档就完成了从原料到有效数据集的蜕变。」

接下来，第十部分，总结与行动。

结论

预训练数据治理分两大阶段：结构化解析（MinerU ，得到 Markdown + 多模态图片描述）与清洗脱敏（去重 ，得到 质量过滤 ，得到 隐私脱敏）。

MinerU 是异构文档统一转 Markdown 的首选工具，pipeline 模式可在 CPU 环境运行；图片信息必须用多模态模型翻译为文本。

去重采用 MD5 精确 + MinHash LSH 近似两级策略，并查集处理传递性重复，threshold 建议 0.7~0.9 小样本调参。

质量过滤以规则为主（字数、特殊字符、广告关键词），模型仅判断存疑项；隐私脱敏分正则 + 模型两段式，保留 CVE 等技术信息。

多模态描述和脱敏结果均需 5%~10% 抽检，关键报告全量人工复核。

创建 MinerU conda 环境，对 raw_docs 目录执行 mineru -p 批量解析。

配置百炼 API Key，编写正则批量提取图片引用并调用 qwen3.8-flash 生成描述。

实现 exact_dedup + MinHash LSH 两级去重，在小样本上调试 threshold。

编写 quality_filter 规则函数，对存疑文本接入 qwen-plus 二次判断。

实现 desensitize 正则 + model_desensitize 模型脱敏，抽检 5%~10% 确认合规。
