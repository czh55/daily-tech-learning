认知纠偏

误解：Accepted 等于明天就能 import 标准库 ordered.Map。实际是 golang.org/x/exp/collection/sorted 实验路径，实现与 API 仍可微调。

接下来，第三部分，反驳。

反驳

对立视角：极简 Go 派 / 「标准库够用了」开发者

再塞平衡树 Map 只会膨胀标准库认知负担，大多数人用 slices.Sort 就够了，官方有序容器是在替懒开发者买单且拖慢编译与二进制。

接下来，第四部分，【概念拆解卡】原生 map 解决不了什么。

在讲什么问题，排序输出只是冰山一角，还有边界元素、区间、排名、反向遍历。

关键理解，手动 slices.Sort(keys) 无法高效维护动态集合上的范围与名次操作。

和其他概念关系：对标 Java TreeMap、Rust BTreeMap，Go 长期缺官方泛型有序容器。

怎么落地用：监控时间序列、排行榜、窗口聚合时评估 sorted.Map 而非每次全量排序。

边界说明，纯 KV 查找 dominance 仍是哈希 map O(1) 均摊。

原文依据，#60630 因缺少可遍历抽象拖延至 Go 1.23 迭代器落地。

接下来，第五部分，【方法/工具卡】sorted.Map 核心 API 怎么用。

核心思路：构造时传入比较函数，Key 不必 cmp.Ordered，自定义结构体可按 Age 等字段排序。

操作步骤，① sorted.NewMap(cmp.Compare[int], ...)；② for k,v := range m.All() 正序，Backward() 逆序；③ Min()/Max()；④ m.Span().From(lo).To(hi) 区间；⑤ Index/Nth 查名次。

选型条件，需要有序索引、窗口扫描、Top-N 时选 sorted；高频点查改为主选 map。

避坑，比较函数须严格弱序一致，cmp 结果为 0 的 Key 视为等价。

对比相邻方法，第三方 treemap 缺少与 iter 生态、未来标准库路线图对齐。

接下来，第六部分，【跨概念对比表】原生 map vs sorted.Map。

遍历顺序，随机，按键排序，业务要顺序必选 sorted

复杂度，O(1) 均摊查找，O(log N) 树结构，写多读少排序场景付 log 代价

范围查询，自实现，Span API，时间戳窗口首选

自定义序，不支持，比较函数，复杂 Key 友好

接下来，第七部分，【决策/选型表】集合类型怎么选。

缓存、计数器，map / collection/set，哈希快，sorted，无顺序需求

定时事件表，sorted.Map，Span + Min，每次 Sort keys，动态维护昂贵

优先队列，collection/heap，堆专精，sorted 当堆，语义不对

实验新业务，x/exp sorted 试点，跟官方 API 演进，fork 老旧 treemap，迁移成本高

接下来，第八部分，【避坑清单卡】跟進提案时别踩坑。

坑名，依赖 map 遍历顺序做逻辑。原因：Go 刻意随机化。解法：显式排序或 sorted.Map。严重程度：致命。

坑名，Accepted 就锁死 API 写生产依赖。原因：仍在 x/exp 打磨。解法：抽象接口+关注 release note。严重程度：小心。

坑名，所有集合一律 sorted。原因：log N 与内存树开销。解法：按访问模式选型。严重程度：小心。

提案时间线：2023 提出 ，得到 1.23 迭代器 ，得到 2026-11-12 Accepted；语言特性与库 API 协同演进是 Go 风格。

接下来，第九部分，【心法/原则卡】Collection API 的长期主义。

原则，先 x/exp 试错，哈希 set 与 sorted 各守其位，再考虑标准库晋升。

为什么重要，避免再出现「社区五个 treemap 互不兼容」碎片化。

怎么落地，新业务读 #60630/#69230，在分支上试用 sorted 并反馈 issue。

适用边界，极致性能自定义内存布局仍可能自研结构。

原文支撑：Austin Clements「No change in consensus, so accepted」标志设计共识收敛。

接下来，第十部分，总结与行动。

结论

#60630 Accepted，sorted.Map/Set 将提供排序遍历、Min/Max、Span、Index/Nth 等有序索引能力。

依赖 Go 1.23+ iter.Seq 与自定义比较函数，Key 类型更灵活。

与 #69230 set、hashed、heap 共同构成 x/exp Collection 体系。

性能 trade-off：O(log N) 换有序语义，不可替代哈希 map 的点查场景。

审计代码中「sort keys 再 range map」热点，标记可换 sorted.Map 的路径。

在 Go 1.23+ 项目引入 golang.org/x/exp/collection/sorted 做 POC。

阅读 #60630 最终 API 与比较函数契约，写单元测试覆盖 Span 边界。

关注 set 与 sorted 包版本，规划与第三方 treemap 的迁移窗口。

向团队同步：Accepted 是里程碑，生产采用仍看 x/exp 稳定性与 std 晋升时间表。
