一句话概括。本文解决的核心问题是：当 AI Agent 获得 Shell 权限后，如何不靠 Prompt 自律，而在 Harness + 操作系统层面用文件系统与网络两条硬边界限制「能读什么、能改什么、能连哪里」，并让权限申请与授予彻底分离。

接下来，第一部分，核心概念关系。

关系脉络如下：用户任务，然后Agent Loop，然后Harness 裁决，然后Sandbox 执行，然后子进程树继承

接下来，第二部分，认知纠偏。

认知纠偏

误解：给 Agent 装 Docker 就安全了。原文强调真实开发环境（Xcode、本地 DB、私有工具链）无法整包搬进容器；Codex 在宿主机上用 Seatbelt / Bubblewrap+seccomp / MXC 做进程级强制隔离。

接下来，第三部分，反驳。

反驳

对立视角：「云端 Agent 全用 K8s Job + 无特权容器就够了」

本地编码 Agent 必须触摸真实工具链与模拟器，整包容器化要么牺牲能力要么把高危操作放回宿主机却不设进程树级强制约束——那正是 Codex 拒绝「只上 Docker」的工程理由。

接下来，第四部分，【概念拆解卡】纵深防御 vs System Prompt。

在讲什么问题，Prompt 只能「劝」模型别作恶，无法从内核阻止读 SSH 密钥、改 Git Hooks、外传 API Key。

关键理解，Sandbox 限制进程实际能访问的文件与网络；Harness 负责把模型工具调用映射到受控执行。

关系：对齐/训练仍重要，但 Agent Runtime 必须是一等安全设施——模型能力决定「能做什么」，沙箱决定「犯错时破坏上限」。

落地：默认 :workspace 可改代码但保护 .git、.codex；网络默认关，需要时再开代理白名单。

边界：沙箱不保证行为符合用户意图，也不覆盖宿主机被污染、代理未覆盖的外传通道。

原文依据，「不要把安全寄托在模型是否遵守指令上。」

接下来，第五部分，【跨概念对比表】Docker 容器 vs 原生 Sandbox。

环境保真，需复制工具链，直接用宿主 Xcode/本地服务，本地 Agent 偏原生

隔离粒度，容器边界，单命令进程树 + OS 机制，命令级更贴 Harness

典型场景，多租户云端、不可信代码，个人机器上的编码 Agent，场景互补非替代

跨平台，镜像统一，抽象 Sandbox API 屏蔽 Seatbelt/bwrap/MXC，Harness 写一次

接下来，第六部分，【方法/工具卡】两条边界：文件系统 × 网络。

核心思路：读取权限与外发权限分开管——读到密钥 ≠ 能上传。

文件系统：read / write / deny；工作区外常保留只读以满足编译器读 SDK。

网络：禁止 / 全开 / 代理+域名规则（拒绝优先于允许）。

步骤：① 选 Permission Profile ，得到 ② 必要时 network_proxy + domains ，得到 ③ Harness 调用 spawn_command_under_sandbox。

避坑，代理域名控制不是完整 DLP；要叠审批与其他防护。

接下来，第七部分，【决策/选型表】权限请求三模式。

use_default，当前 Profile 默认权，无需额外，需突破工作区写保护时

with_additional_permissions，沙箱内增量权限，Harness/用户审批，模型自行批准（禁止）

require_escalated，脱离当前沙箱，显式人工或策略，无人值守全自动

接下来，第八部分，【避坑清单卡】进程树与 MCP 盲区。

子进程逃逸：只约束首个 Shell 不够——go test 拉起的编译器/脚本必须继承同一 Sandbox。

工具权限：工具/MCP Server 不能默认继承全盘权限；codex sandbox 可为 stdio MCP 单独定文件/网络策略。

企业治理：用户可配 Profile，但不能突破组织底线；Permission Profile 在 config.toml 复用。

严重程度，改 .git hooks、自改 .codex 策略 ，得到 致命。

接下来，第九部分，【心法/原则卡】Agent Runtime 是一等基础设施。

原则，申请权与授予权分离——模型可「要网络」，不能「批网络」。

落地：自建 Agent 工具可参考统一 Sandbox API：命令 + cwd + env + profile + proxy。

边界：不要把所有 Agent 塞进同一权限级；本地环境本身也可能是攻击面。

原文支撑：操作系统级沙箱已从可选功能升级为 Agent Runtime 的一等基础设施。

接下来，第十部分，总结与行动。

结论

安全靠 Harness+内核强制执行，不靠 Prompt 口头约束。

文件与网络双边界解耦，默认保护 .git/.codex，网络可走代理白名单。

子进程树继承 + 权限申请/授予分离，防 Shell 与 MCP 权限膨胀。

原生跨平台 Sandbox 服务真实开发环境；容器仍适合云端强隔离。

审视自家 Agent：工具执行路径是否有独立于模型的权限裁决层。

为「读敏感配置」与「出网」分别设策略，默认 deny outbound。

stdio MCP/插件进程单独 Profile，禁止继承 Agent 全盘写权限。

在配置里固化 Permission Profile，避免每次会话手工点批准。
