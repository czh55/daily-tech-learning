欢迎收听每日技术学习语音讲解。本期主题，每个 AI 工程师都应该知道的 20 个循环设计模式。标签包括Loop Design Patterns、Loop Engineering、Agent Harness、自我进化。本次讲解预计时长 约 13 到 14 分钟，共 11 个部分。好，我们开始。

一句话概括。本文解决的核心问题是：当 Prompt 杠杆见顶、单次模型调用无法支撑生产级任务时，AI 工程师应如何系统性地设计「生成，得到评估，得到学习，得到改进」的循环，让 Agent 从脆弱 Demo 走向可自我进化的工业级架构。

接下来，第一部分，核心概念关系。

关系脉络如下：质量提升，1-5 出库前质检，然后记忆循环，6-10 从历史学习，然后规划循环，11-15 动态调整，然后探索循环，16-18 多路径寻优，然后系统优化，19-20 元循环

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「Agent 才是未来，模型越聪明系统越好」—— Rahul 指出 Agent 只是干活的工人，Loop 才是让工人每天自我进化的机制；顶尖团队早已不再死磕 Prompt，而是在构建更好的循环。

接下来，第三部分，反驳。

反驳

对立视角：「极简 Prompt 派」/ 快速 MVP 倡导者

二十种循环是过度设计——多数产品一周上线、用户只在乎功能有没有，为工业级 Agent 设计的五层循环会把简单任务拖成运维噩梦，算力与延迟成本远超收益。

接下来，第四部分，【概念拆解卡】Agent vs Loop vs 单次调用。

在讲什么问题，为什么年薪百万与普通工程师的差距不在 Prompt 措辞，而在循环设计？

核心机制，老方法：输入 Prompt ，得到 获得 Response ，得到 结束（临时工干完就走）。新方法：生成 ，得到 批判 ，得到 重写 ，得到 打分 ，得到 重试 ，得到 记忆 ，得到 改进，周而复始直到达标。

关键理解，生产级最强 AI 系统全部由 Loop 支撑，而非 Single Model Call；竞争维度已从单次调用转向 Loop Engineering。

典型场景，代码纠错、文案质检、长程调研、受监管内容生成——任何「第一次尝试失败后需自主变好」的系统。

边界说明，简单问答、一次性短链路 Demo 仍可用单次调用；需持续改进、有质量阈值、可量化评估的任务必须用循环。

原文：「Agent 只是一个干活的工人。Loop 才是让这个工人不断改进的机制。」

接下来，第五部分，【方法/工具卡】质量提升循环（模式 1-5）。

核心思路：在输出离开系统前，用独立评估角色把质量推到极限；生成者往往不是评判自己输出的最佳裁判。

操作步骤，

1. 生成-批判-重写：Generator 出初稿 ，得到 Critic 挑刺 ，得到 Generator 重写，循环至达标（文案、代码、报告）。

2. 打分-重试：while score < threshold: output = generate(); score = evaluate()，生成者不知正在被考核，Evaluator 掌握标准。

3. 多重批判者：正确性 / 风格 / 安全 / 领域四维度独立审核，全部通过才出库（医疗、法律、财务）。

4. 对抗式批判：Critic 唯一任务是摧毁答案——「哪些假设不成立？怀疑论者怎么反驳？」

5. 评审团共识：五个 Evaluator 联合打分抹平噪声，高共识才推进（容错率极低场景）。

避坑：用一个模型既生成又自评——角色隔离才是精髓；单裁判打分伴随噪声，关键场景需 Ensemble。

接下来，第六部分，【跨概念对比表】五类循环核心差异。

核心目的，出库前质量极限，从历史学习变聪明，现实变化时动态调路线，多路径榨出最优解，循环本身自我优化

代表模式，生成-批判-重写，Reflexion 反思，Plan-Execute-Replan，Branch-and-Explore，Prompt 自动优化

关键产出，达标输出，错题本/成功模式库，收敛的螺旋规划，最优分支，进化后的 Prompt/工作流

适用上限，质量可量化评估时，任务可重复、有历史，长周期、强依赖步骤，算力充足、需深度推理，有测试集与可测指标

一句话结论，分离生成与评判，失败只摔一次，规划不是圣旨，别押注单一路径，用循环优化循环

接下来，第七部分，【决策/选型表】何时启用哪类循环。

文案/代码需反复打磨，生成-批判-重写 (#1)，两角色流水线，Critic 总能找到盲点，单次生成 + 人工返工，无法自动化质量收敛

质量可客观量化，打分-重试 (#2)，极度简单却常被低估，主观感觉「差不多」，无阈值则无法自动停止

Agent 反复在同一处失败，Reflexion + 错误档案库 (#6+#8)，教训写入 Context 重试；新任务前检索错题本，每次从零开始，系统不会比第一次更聪明

外部环境动态变化，Plan-Execute-Replan (#11)，螺旋收敛而非瀑布圣旨，固定 Pipeline 步骤 1，得到2，得到3，碰撞现实后规划碎落一地

架构/文案多方案比选，分支探索 (#16)，保守/激进/创意并行生成后选最优，单路径生成，错过更优解

延迟/成本/质量三角博弈，工作流自我重构 (#20)，自动并行化、换廉价模型、插 Critic 拦截，人工调参 Prompt，无法随运行数据持续进化

接下来，第八部分，【避坑清单卡】记忆与规划类常见失效。

坑名，只记失败不记成功，或记忆无限膨胀成垃圾。

原因，忽略 Success Pattern Loop (#9)；原始记忆未压缩 (#10)。

解法，每 N 条记忆触发压缩；任务结束固化「决策-结果-若重来」三件套 (#7)。

严重程度，小心——第 6 个月表现应与第 1 个月天壤之别，否则记忆层未生效。

原文：「无限的、杂乱的原始记忆，等同于无法使用的垃圾。」压缩后应升华为抽象规律：「X 会直接导致失败，执行前务必优先检查 X。」

规划陷阱：把最初规划当一成不变的圣旨；约束满足循环 (#15) 要求所有硬性约束（预算、延迟、无幻觉）全通过才算完工，一条 business rule 未过则内部不算完成。

接下来，第九部分，【心法/原则卡】统一公式与范式转移。

原则，行动 ，得到 观察 ，得到 评估 ，得到 调整——第一枪产出永远是粗糙起点，Loop 是唯一熔炉。

为什么重要，过去式 Prompt，得到Response（一锤子买卖）；进行时 Generate，得到Evaluate，得到Learn，得到Improve（无限进化）。

怎么落地，从模式 #1 生成-批判-重写入手；为可量化场景加 #2 打分-重试；长程任务叠加 #6 Reflexion + #11 重规划；成熟后引入 #20 工作流自我重构。

适用边界，树搜索 (#17) 算力消耗极高，仅用于复杂推理链与代码库级 Debug；Prompt 自动优化 (#19) 需有测试集与 evaluate 函数。

原文：「去构建循环吧，让它在你睡觉时，替你改变世界。」

接下来，第十部分，总结与行动。

结论

Agent 是工人，Loop 是进化机制——顶尖团队构建的是循环，不是更好的 Prompt。

20 个模式分五类：质量提升、记忆、规划、探索、系统优化，共享「行动，得到观察，得到评估，得到调整」公式。

最基础也最重要的是生成-批判-重写；记忆循环让系统「只摔一次」；规划循环拒绝把计划当圣旨。

探索循环通过多路径寻优；系统优化循环实现「用循环优化循环」的元能力。

单点突破的运气永远敌不过系统级闭环的确定性——架构图里充满自我诊断飞轮才算掌握 AI 系统工程心法。

为当前 Agent 项目选一个最痛的质量瓶颈，实现生成-批判-重写最小闭环（模式 #1）。

若质量可量化，加上 while score < threshold 的打分-重试循环（模式 #2），生成者与评估者角色隔离。

建立错误档案库：每次失败写入检索库，新任务启动前先查类似失败记录（模式 #8）。

长程任务用 Plan-Execute-Replan 替代固定 Pipeline，每 N 步做进度自评（模式 #11+#14）。

有测试集后启动 Prompt 自动优化循环，让最强 Prompt 由系统繁衍而非人工手写（模式 #19）。
