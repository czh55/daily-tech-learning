认知纠偏

误解：切片 [i32] 可以当栈变量或 fn 按值参数。实际上 [i32] 是 DST，编译期大小未知，只能藏在 &[i32] 等指针后；fn foo(s: [i32]) 会直接 E0277。

接下来，第四部分，【概念拆解卡】四种相关类型。

在讲什么问题，四个长得像的类型为何不能互换？

关键理解，[T; N] 长度是类型一部分；[T] 无固定大小；&[T; N] 是 8 字节瘦指针；&[T] 是 16 字节胖指针（地址+len）。

和其他概念关系：Vec<T> 拥有堆数据，&[T] 只是借用视图，无 capacity。

怎么落地用：验 size_of：定长数组 12B（3×i32），&[i32] 类型本身 16B。

边界说明，DST 不能单独存在；大数组按值传参拷贝贵，应优先引用。

原文依据，「瘦指针靠类型记住长度，胖指针靠值记住长度。」

接下来，第五部分，【跨概念对比表】C++ / Go / Rust 序列视图。

定长数组传参，退化为指针丢长度，整体拷贝，按值或 & 引用，C++ 需 span 补丁

通用只读视图，std::span（C++20），[]T（24B 含 cap），&[T]（16B），语义最接近 span

扩容，视图不能，append 可长，视图不能，Vec 能，Rust 拆清所有者

安全，无，无借用检查，借用检查器，悬垂/别名写受控

接下来，第六部分，【决策/选型表】函数形参怎么写。

只读任意长度，&[T]，标准库惯例，[T; N] 按值，长度写死+拷贝

就地改元素，&mut [T]，可改不可增删，&mut Vec，除非真要扩容

必须恰好 N 个，&[T; N] 或 const N，协议头/矩阵，为每 N 复制函数，用 const 泛型

小型 Copy 数据，[T; N]，如 [f32;2] 坐标，大数组按值，栈拷贝爆炸

要 push/pop，&mut Vec<T>，视图无容量，&mut [T]，无 push API

接下来，第七部分，【方法/工具卡】自动转换与反向技巧。

核心思路：数组，得到切片用 Unsized Coercion；Vec/String/Box 用 Deref Coercion，均在调用点零成本完成。

操作步骤，① 参数写 &[T] ，得到 ② 传 &arr / &v / &arr[i..j] ，得到 ③ 需定长时用 s[..N].try_into()。

选型条件，泛型接受多种容器时 &[T]；协议固定宽度用 try_into 或 const N 泛型。

避坑，勿混淆两套 coercion；try_into 长度不匹配返回 Err，别用 into 盲转。

对比相邻方法，impl AsRef<[T]> 更宽但更抽象；&[T] 直白且无额外 trait 约束。

原文引用：口诀——参数想通用写 &[T]；想严格才写 &[T; N]。

接下来，第八部分，【避坑清单卡】新手第一道暗礁。

坑名，fn foo(s: [i32])。原因：DST 不能入栈。解法：改 &[i32]。严重程度：致命（不编译）。

坑名，以为 [i32;3] 与 [i32;4] 同类。原因：长度入类型。解法：用切片或泛型 N。严重程度：小心。

坑名，在 &mut [T] 上 push。原因：视图不负责容量。解法：&mut Vec。 严重程度：小心。

接下来，第九部分，总结与行动。

结论

Rust 把序列拆成数据（[T;N]、[T]）与借用视图（&[T;N]、&[T]），[T] 只能经胖指针使用。

函数形参默认 &[T] 或 &mut [T]，兼容数组、Vec、子区间。

Unsize 与 Deref 两套转换机制不同，皆在调用处零成本。

定长需求用 &[T; N]、const 泛型或 try_into，小数组才可按值 [T; N]。

相对 C++ span 与 Go slice，&[T] 无容量、不可扩容，安全靠借用检查。

把仍写 [T; N] 按值入参的 API 审一遍，大数组改 &[T]。

在 playground 打印 size_of 验证瘦/胖指针差异。

解析二进制头时用 try_into 做运行时长度校验。

矩阵类 API 尝试 fn foo<const N: usize>(arr: &[T; N])。

思考题：对比 impl AsRef<[T]> 与 &[T] 在 crate 公开 API 上的取舍。
