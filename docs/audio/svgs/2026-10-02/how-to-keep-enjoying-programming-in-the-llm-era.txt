一句话概括。本文解决的核心问题是：当大模型能替你写代码时，如何通过「规划与调研交给 AI、核心实现亲手写」的分工，避免代码库变成只有 Agent 能维护的荒原，同时保住手感、责任与长期可维护性。

接下来，第一部分，核心概念关系。

关系脉络如下：规划 Planning，AI 记账、人决策，然后调研 Research，人机并行验证，然后编码 Coding，人类主笔，然后GAN 式审稿，生成 vs 挑刺，然后收尾/重构，可交 Agent

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「少用 AI 才能保住乐趣」。原文立场是不是反 AI，而是反对把编写核心实现全权外包；乐趣来自亲手把想法敲成可维护代码，AI 更适合事务性、可审稿的环节。

接下来，第三部分，反驳。

反驳

对立视角：「全栈氛围编程 / 交付速度优先派」

在产品窗口和人力紧缺时，坚持核心手写会把迭代速度输给「几乎不会编程却坐拥巨额 Claude 额度」的对手，乐趣换不来上线。

接下来，第四部分，【概念拆解卡】「LLM 荒原」与技能退化。

在讲什么问题，全权让 Agent 写代码后，人类失去读懂与排障能力，代码库对人类变成陌生领地。

核心机制，模型擅长生成「能跑」但未必可读、可长期维护的代码，几周不亲手写就会手感退化。

关键理解，维护权与乐趣同源——放弃手写等于放弃对系统的长久掌控。

典型场景，面对整文件 AI 生成物却不知从哪查 bug 时，正是荒原信号。

边界说明，清理 FIXME、重复样板、低风险重构仍可交给 Agent；从零设计复杂系统不宜甩手。

turion：LLM 更擅长写「只有它自己以后会继续维护」的代码。

接下来，第五部分，【方法/工具卡】一起规划，但你来写代码。

核心思路：拒绝主流「规划完就放手让 Agent 写」；让 LLM 考古仓库、列 todo、提示坑，敲键盘由人完成。

操作步骤，① 让 LLM 读仓库并输出带 frontmatter 的 Markdown todo；② 决策权在人，让 AI 提问而非替你做关键决定；③ 调研时人与搜索引擎并行，要求引用存档；④ 按 todo 亲手实现；⑤ 用审稿 Agent 过滤规划与代码；⑥ token 中断时切换离线任务清单。

选型条件，你喜欢编程、在乎代码库真实状态、需要早期发现错误方案时，优先此模式。

避坑，只写 3 个典型 case 就让 AI 复制剩余 7 个，往往说明该抽象（如 Traversable）而非复制粘贴。

落地：规划文档持久化到文件，避免上下文塞满后静默丢内容。

接下来，第六部分，【跨概念对比表】主流 Agent 流 vs turion 流。

代码库认知，易积累「氛围编程」屎山，人始终掌握真实状态，责任与可读性在人这边

错误发现，自主 Agent 可能沿错方向狂奔，人类更早识别糟糕方案，规划好 + 手写 = 敏捷无烦人流程

技能曲线，几周不写即退化，手艺持续在线，乐趣与能力同向

适合任务，重复劳动、小收尾，核心设计与实现，分工而非二选一

接下来，第七部分，【决策/选型表】编程任务谁来做。

冗长讨论整理成 todo，LLM 记账 + 人拍板，自然语言持久化清单，AI 做关键架构决策，看不懂它的提问说明上下文或精力有问题

技术调研，Agent 检索 + 人同步搜，追问依据，约一半它会自纠，直接采纳 AI 结论，会埋技术债与尴尬错误

核心库 / 奇怪 API（如 PowerShell），人主导，LLM 当搜索，模型易收敛到「大家都这么干」，指望 LLM 维护原语，hasufell：核心库场景不及预期

PR / commit 沟通，人写主文，AI 文折叠在 details，编程是社交活动，整份 AI PR 描述甩给同事，不是沟通，只是工具输出

接下来，第八部分，【避坑清单卡】精神石棉与平台依赖。

车轱辘话：长期读不懂的 AI 废话消耗心智。解法：多和真人聊代码，只读经审稿 Agent 打磨后的产出。严重程度：小心。

前沿模型迷信：高能耗、黑盒信任难、token 不透明。解法：小模型能搞定优先小模型，预留开源替代路径。严重程度：小心。

token 耗尽：视为服务中断而非自己买少了。解法：像飞机上工作一样准备离线 todo。严重程度：致命（对连续交付预期）。

AI 表面自信：消解你对判断的不安全感。解法：核心库与低容错场景保持怀疑。严重程度：致命。

接下来，第九部分，【心法/原则卡】有机园丁，而非化肥狂魔。

原则，温和使用 LLM 辅助，产出约两倍于不用时的可持续节奏，而非短期全氛围编程的夸张倍数。

为什么重要，短期化学施肥产量亮眼，长期土壤（技能与代码库健康）可能透支。

怎么落地，硬规则——任何 LLM 产出未经自动化审稿不采纳；让 AI 审你手写代码以补盲区。

适用边界，评论区亦有人靠 AI 首次实现过去做不到的想法；团队可探索「AI 派」与「零 AI 派」共存政策，但需明确评审与 commit 规范。

接下来，第十部分，总结与行动。

结论

甩手掌柜式 AI 编码的隐性成本：可维护性、个人手艺、团队信任会在出问题时集中兑现。

AI 更适合记账员、调研助理、GAN 式审稿人；决策与手感留在人侧。

「一起规划、你来写代码」是 turion 自认的游戏规则改变者，兼顾清单清晰与编码心流。

警惕 LLM 文字污染与平台 token 策略绑架工作流——需离线清单与沟通规范。

核心库与奇怪平台 API 上，社区经验支持更保守的 AI 使用尺度。

把当前迭代讨论让 LLM 整理成带 frontmatter 的 Markdown todo，但关键决定自己拍板。

下一次调研要求 Agent 附引用，并自己用搜索引擎抽查同一主题。

选一个小功能：让 AI 只列改动点与坑，实现由你亲手完成。

加一道「审稿 Agent」：规划与（必要时）生成代码都必须过 automated review。

准备一份 token 中断时可离线推进的任务清单；PR 描述以人手写为主。
