一句话概括。本文解决的核心问题是：当智能体周请求量暴涨 9.4 倍、70% PR 由 AI 主导时，Uber 如何把总 AI 支出锁在 4 月以来的水平——不是靠少用，而是把总花费拆成六个可度量变量，并在模型路由、Token 减重、请求效率、组织可见性四条杠杆上逐项消灭零价值消耗。

接下来，第一部分，核心概念关系。

关系脉络如下：用户数，× 人均会话，然后每会话轮次，× 每轮请求，然后每请求 Token，× 单 Token 价，然后总花费

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「AI 用量涨 7 倍，账单必然爆炸」。Uber 用固定模型版本的对照实验证明：每千次请求成本降 34%、每会话成本降 52%——成本失控是工程问题，不是用量与价格的宿命线性关系。

接下来，第三部分，反驳。

反驳

对立视角：「先规模化再谈 ROI」派 · 国内赶 AI 编程 KPI 的管理层

Uber 有 3600 技能、统一网关和 2400 万节点图谱——中小团队照搬 CLI 化与 Context Graph 的前置工程成本，可能比先放任账单增长更拖慢交付。

接下来，第四部分，【概念拆解卡】软件工厂四层架构与成本可控性。

在讲什么问题，为什么 Uber 把 AI 使用场景分成四个层级，且越往上越能拿捏成本与质量。

核心机制，从专用工具 ，得到 交互式 Harness ，得到 托管智能体 ，得到 自治智能体，任务边界越明确、评测基准越可建，模型选型越能走帕累托前沿而非「一个旗舰模型打天下」。

关键理解，3600+ Agent Skills、日执行 3 万+ 次、70% PR 由 AI 主导——增长发生在托管/自治层，团队能完全掌控 Harness、路由与运营开销。

典型场景，uReview 全量 PR 评审、CI 失败自愈、on-call 分诊——边界清晰、可批量评测的 SDLC 环节。

边界说明，交互式终端会话需求五花八门，逐个优化难；战略方向是把人类驱动流程迁移到托管智能体舰队。

原文：「运营一支专属评测基准 + 帕累托最优模型武装到位的托管智能体舰队，天然更省钱，也更容易规模化。」

接下来，第五部分，【方法/工具卡】MCP CLI 化 + Tool Search + Code-Mode。

方法名：Token 减重三板斧 · 标签：MCP 网关、Shell 执行、脚本批处理

核心思路：标准 MCP 预加载 100+ 工具 Schema 约 5–7 万 Token 且每轮重发；CLI 化让 Schema 零进上下文，Tool Search 按需加载，Code-Mode 把轮询/翻页压进子进程只回摘要。

操作步骤，1) 1000+ MCP 映射为 CLI 命令经统一网关 ，得到 2) 模型先搜索工具目录再加载定义 ，得到 3) 高频 Server 部署 25+ Code-Mode 技能默认走脚本路径 ，得到 4) SaaS MCP 同样 CLI 化并写专属技能封装工作流

选型条件，话痨型协议（SQL 轮询 2–5 次）、批量 N 轮交互、第三方 SaaS 49 工具 2.2 万 Token Schema——优先 Code-Mode。

原文：「SELECT * 宽表查询 LLM 工具模式 143 万 Token vs Code-Mode 900 Token，约 100% 节省。」

落地建议：核算团队 MCP 预加载 Token；把内部工具网关 CLI 化；为 TOP 访问 MCP 写 Python 循环技能，中间状态不进模型视野。

接下来，第六部分，【决策/选型表】模型、缓存 TTL 与 Harness 默认值。

托管智能体模型选型，真实 PR/任务建 benchmark ，得到 帕累托前沿选模，uReview 换模 F1 升、单次评审成本大降，拍脑袋选旗舰，无法在成本-效果平面上定位最优

交互式子智能体，默认路由便宜模型，主模型拆解+评估，子任务边界清晰，不需旗舰推理，子智能体也用 Opus 级，Requests/Turn 杠杆失控

主会话 Prompt Cache TTL，1 小时（工程师常停顿 >5 分钟），避免 5 分钟 TTL 频繁失效全价重建，盲目用 5 分钟默认，1h 写入 2× 溢价，但停顿分布决定经济学

子智能体 TTL，保留 5 分钟，短生命周期单一任务，与主会话同 TTL，浪费长缓存写入溢价

交互式 Harness 默认，40 万 Token 压缩阈值 + 中等推理强度，平衡表现、缓存命中、输出 Token 倍数计费，开满 100 万上下文 + 高推理，重复输入与推理 Token 成本最高

接下来，第七部分，【跨概念对比表】MCP 直连 vs CLI 网关 vs Code-Mode。

会话启动 Token，5–7 万 Schema 先入上下文，接近零（按需解析），零中间轮询进上下文，隐性杀手在「用户还没打字」

轮询型任务，每步一轮模型交互，仍可能多轮，Python 循环子进程跑完，小结果集也能省 50%+ 固定开销

SaaS 多工具 Server，2–3 个 Server Schema 超编辑文件，CLI 映射 + 专属技能，封装常见工作流，厂商暴露全能力，客户必须二次封装

适用边界，工具少、交互简单，千级工具库扩容，边界清晰可脚本化子任务，三者互补而非互斥

接下来，第八部分，【方法/工具卡】AI Context Graph 压低 Requests/Turn。

在讲什么问题，缺上下文的智能体不会快速失败，而是缓慢、反复、用越来越长的上下文搜索。

核心机制，2400 万节点、8000 万边、86 种节点类型，整合 30+ 内部系统——服务、团队、故障、PR、架构文档、表使用历史。

关键理解，有图谱：38 秒答对分析师常用表；无图谱：20 分钟、2 个子智能体、3 次报错、错误结论「数据集无法查询」。

怎么落地，数亿行代码 + 数千张表场景，优先把「找信息」结构化，再谈「写代码」。

与 Prompt Cache 的关系：图谱减少无效搜索轮次，Cache 减少重复前缀付费——一个降 Requests/Turn，一个降 Tokens/Request。

接下来，第九部分，【避坑清单卡】16 类浪费模式与治理反模式。

坑名，在用户输入前预加载 10 万 Token 系统指令与工具定义

原因，MCP Schema 预加载 + 臃肿系统 Prompt 叠加。

解法，CLI 化、Tool Search、会话分析仪表盘 trace 自动识别反模式。

严重程度，致命——每轮对话复利放大。

40KB MCP 响应滞留上下文：后续每一轮都为它重复付费；应压缩或及时剔除。

旗舰模型跑简单多轮会话：Session Analysis 标注「模型路由不合理」——应用更便宜模型完成。

硬性配额封顶：工程师束手束脚；Uber 用状态栏实时计数 + 50%/80%/100% Slack 提醒 + 快速升档审批。

无度量先优化：没有每千次请求成本、每会话成本、托管智能体单位产出成本，优化只能是拍脑袋。

接下来，第十部分，【心法/原则卡】成本可见性与「工厂成熟度」。

原则，把模糊的「AI 太贵了」转化为可拆解、可量化、可逐项优化的工程问题。

为什么重要，7 倍周活、9.4 倍请求量与总支出持平并存——证明采用度与成本可解耦。

怎么落地，建立 Portfolio / Unit Economics / Model Economics / Driver Decomposition / Managed Agent Outcomes 五维监控；新托管智能体统一流程：定产出指标 ，得到 建 benchmark ，得到 帕累托选模。

适用边界，具体降本幅度因代码库规模、团队构成、工作流而异；方法论普适，数字不可照搬。

原文：「AI 编程开销的失控，本质上是一个可以被工程化解决的问题——关键不在于死磕更低的单价，而在于系统性地消灭零价值 Token 消耗。」

接下来，第十一部分，总结与行动。

结论

总花费 = 用户×会话×轮次×请求×Token×单价；中间三项是优化主战场，前两项应鼓励增长。

Price/Token：真实工作 benchmark + 帕累托前沿选模；子智能体默认便宜模型是最大杠杆之一。

Tokens/Request：40 万压缩阈值、Prompt Cache TTL 按停顿分布调、MCP CLI 化清零 Schema 预加载、Code-Mode 消灭轮询复利。

Requests/Turn：AI Context Graph 把「找信息」从 20 分钟探索压到 38 秒精确查询。

可见性：状态栏实时成本、16 类反模式仪表盘、分级预算而非硬封顶——文化与技术同为杠杆。

建立每千次请求成本、每会话成本、托管智能体单位产出等细粒度指标，再启动优化。

审计 MCP 预加载 Token；评估 CLI 网关 + Tool Search 改造 ROI。

分析团队会话停顿分布，调整 Prompt Cache TTL（主会话 vs 子智能体可不同）。

为 SQL/轮询/批量类工具编写 Code-Mode 技能，中间状态不进模型上下文。

上线成本可见性：终端计数器或 trace 仪表盘，识别模型路由与上下文臃肿等浪费模式。
