一句话概括。本文解决的核心问题是：工业界默认的「Markdown 文件树」式 Agent 长期记忆，在持续增长、重复与矛盾信息并存时，整理是否真的可靠、整理能否换来更准的答案，以及模型与工具集各自扮演什么角色。

接下来，第一部分，核心概念关系。

关系脉络如下：管理 Agent，写入 · 合并 · 维护，然后记忆 Store，路径树 + 描述 + 正文，然后搜索 Agent，带引用作答，然后执行 Agent，技能轨迹蒸馏

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：记忆越整理、Agent 自主重组越多，答案就越准。论文显示整理的核心收益是降低检索成本；正确率排名会随基准翻转，「分文件夹归档」常比完全自主整理更稳。

接下来，第三部分，反驳。

反驳

对立视角：向量记忆/RAG 架构师 · 「专用表征才配得上 Agent」派

文件树靠路径导航和 BM25 式翻找，语义相近却目录远离的内容照样漏检——工业界图省事用文件系统，是在用可解释性掩盖检索天花板，论文只证明了「便宜」，没证明它真能替代嵌入与图谱。

接下来，第四部分，【概念拆解卡】文件系统记忆与三角色 Store。

在讲什么问题，Claude memory tool、Claude Code 记忆文件夹、Skills 体系都在用同一套路——Agent 自己读写 Markdown 目录树，但几乎无人系统验证其可靠性。

核心机制，记忆库是有根路径树，每文件含路径、一句话描述、正文；文件夹名与 Markdown 标题构成 taxonomy。管理 Agent 维护、搜索 Agent 带引用作答、执行 Agent 在技能场景产出轨迹供蒸馏。

关键理解，同一框架同时覆盖声明式记忆（事实/偏好）与程序性记忆（技能），无需为「记什么」和「怎么做」各建一套系统。

典型场景，编码 Agent 在仓库内用 ls/grep/view 翻找历史决策；长对话问答需引用文件路径与行号。

边界说明，工具集（函数式文件 API vs Shell+正则）会重塑 Store 形态，效果不亚于换模型；不适合指望「换向量库就能替代」的纯语义检索场景。

原文：「一个 Agent，真的能在记忆持续增长、出现重复、矛盾、过时信息的情况下，把这个文件仓库管理得井井有条吗？」

接下来，第五部分，【跨概念对比表】六种记忆形态与整理光谱。

整理成本，零或极低（只搬文件），高（内容结构都变），便宜方案常是工程甜点

检索花费，材料量大时偏高，可腰斩以上，整理买到的是「查得快」

答案正确率，多基准上稳定中游，排名翻转，32k 档甚至最差之一，整理≠提分，无通吃赢家

信息保真，原样保留，压缩版易悄悄丢细节，REAL TALK 场景压缩版正确率近乎腰斩

接下来，第六部分，【决策/选型表】什么场景选哪种记忆策略。

落地建议：先按会话主题建文件夹搬 Markdown，不改动正文；仅在检索账单成为瓶颈时再投入重组或自主整理，并 A/B 测正确率而非只看 token。

材料量小、对话不长，逐字转储或分文件夹归档，整理检索优势缩水，简单分主题文件夹最稳，让 Agent 自由重组，成本高且 PersonaMem 32k 上表现差于 RAG

材料量大、检索成本敏感，重组存档或 Agent-curated，每次读取内容量小，总检索花费可减半，闭卷或纯 chunk RAG，无法利用层级 taxonomy 收窄范围

真实聊天、不能丢细节，重组「保留版」+ 硬性保留每条事实，压缩版在 REALTALK 几乎腰斩正确率，无约束的自由压缩重组，模型默认有压缩丢细节坏习惯

强执行 Agent + 技能记忆，原始 episode log 一字不改，学霸型执行者吃完整上下文更好，过度蒸馏摘要，与弱执行 Agent 最优策略相反，差距可达 10 点

弱执行 Agent + 技能记忆，精炼技能 + 按任务动态指导，学渣需要蒸馏后的可执行提示，甩完整历史日志，超出其消化与遵循能力

接下来，第七部分，【方法/工具卡】taxonomy 五条契约与工具集调优。

核心思路：合格记忆文件须满足五条分类契约：同级可区分、同级相关、父级覆盖子级、距离反映相关性、结构服务于检索。

操作步骤，① 为管理 Agent 写入五条契约到 system prompt ，得到 ② 选工具 harness（读/建/改/删/改名 vs Shell+grep），得到 ③ 要求搜索答案带路径与行号引用 ，得到 ④ 对重组任务加「必须保留每一条事实」硬规则 ，得到 ⑤ 单独评测管理模型与搜索模型。

选型条件，长对话偏分片交叉引用工具集；技能记忆换工具集反而让库更整合并提升任务结果。

对比相邻方法，专用向量库/知识图谱可语义检索，但失去人类可直接打开编辑的可解释性；文件系统记忆胜在零成本扩展与透明 taxonomy。

避坑：别假设数据越多 Store 越分裂——同模型下 32k，得到128k 材料反而文件夹变薄，层级钻进单文件标题；换管理模型同一份对话可长成浅森林、两文件标题栈或最深交叉引用树。

接下来，第八部分，【避坑清单卡】整理、压缩与模型分工。

坑名，迷信「越强管理模型 ，得到 答案越准」

原因，管理 Agent 买到的是整理风格；搜索 Agent 能力才直接兑现答案质量，除非「写」本身出错（如未记录偏好变更日期）。

原文说法：「整理的核心收益是省钱，不是提分」；Agent 自主整理在部分基准上不如分块检索。

解法，预算向搜索模型倾斜；管理侧重点防状态更新写错；规模变大时只有最强管理模型能守住 taxonomy 契约。

严重程度，致命——若把整理当提分手段会选错架构投入。

另一坑：逐字经验日志随规模膨胀，检索必须扫全历史；蒸馏有阈值效应，跨门槛后 Store 内容比执行模型身份更关键。

接下来，第九部分，【心法/原则卡】文件系统记忆的设计空间。

原则，文件系统记忆不是被默认相信却从未检验的假设，而是可系统调优的设计空间——整理、工具、模型、消费者能力各是一根杠杆。

为什么重要，评测多看答案对错、看不见组织形态；实验跨度仍是一段对话量级，距数月人类式演化有差距。

怎么落地，默认从 foldered sessions 起步；重组必加保留事实约束；把工具集与选模型并列调优；按执行 Agent 强弱选择 log vs 蒸馏。

适用边界，论文未否定文件系统路线，但证明「越整理越好」不成立；超长周期记忆演化仍是开放问题。

接下来，第十部分，总结与行动。

结论

UIUC 等首次系统检验「文件系统记忆」：三角色 + 六形态 + 五 RQ，工业默认方案终于有了可量化成绩单。

整理稳定降低检索成本（大数据量可腰斩），但正确率无通吃形态；分文件夹归档常跑赢 Agent 自主整理。

Store 形状由管理模型「性格」主导，非数据规模；工具集更换对形态的影响不亚于换模型。

记忆随时间积累不会用废，但 taxonomy 健康度随规模失守，仅最强管理模型能长期守住契约。

技能记忆最优呈现取决于执行 Agent 强弱：强者要完整 log，弱者要蒸馏与动态指导。

新 Agent 记忆从「会话 Markdown + 主题文件夹」起步，避免一上来全自主重组。

若重组/压缩记忆，在 prompt 写明「必须保留每一条事实」并对比压缩版与保留版。

检索贵时优先投整理与 taxonomy，提分时优先升级搜索 Agent 而非管理 Agent。

把文件 API vs Shell 工具集列为与选模型并列的实验维度。

按执行 Agent 能力选择喂完整 episode 还是精炼技能文件。
