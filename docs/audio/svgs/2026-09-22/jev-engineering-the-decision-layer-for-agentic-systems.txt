一句话概括。本文解决的核心问题是：把「写作、路由、评估、执行」全塞进一次 LLM 补全会导致慢、贵、不可调试；Jev 工程学主张三层解耦——大模型生成、Jev 做有界类型化决策、代码执行与验证——用 Choice/Score/Noul 契约、并行提问与置信度门槛，把分叉从散文解析里解放出来。

接下来，第一部分，核心概念关系。

关系脉络如下：State，证据快照，然后Jev，类型化答案，然后Code，阈值/权限，然后Act，单步动作，然后Verify，读真实世界

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「Jev 要取代大模型」。文中强调互补——创意写作、长文调研仍用 LLM；Jev 只接管答案空间有界、高频重复、输出直接进代码的分叉，且高置信≠事实正确。

接下来，第三部分，反驳。

反驳

对立视角：「一个强推理模型 + 结构化输出就够了」派

把路由塞进长思考仍按 token 付费、仍靠解析 JSON，并行 13 问要串 13 次时延迟与账单不会 magically 消失——专用决策层卖的是有界分叉的工程接口，不是再包装一次 chat completion。

接下来，第四部分，【概念拆解卡】三层权责与 System One 三原语。

在讲什么问题，单一 LLM 包办决策与生成时，故障无法归因到「写错了」还是「选错了」。

核心机制，LLM writes / Jev decides / Code acts；Jev 吃结构化 state + 原子问题，返回答案对象（非段落）。

三原语：Choice（单选+分布+置信度）、Score（标尺+置信度）、Noul（是/否概率 0–1）。

状态设计：goal / evidence / rules / available_actions / previous_actions——传证据不传散文；每步外部动作后重建 state。

边界：数学日期计算、开放式创作、巨型脏 state 仍不适合 Jev；提示词注入对类型化输出仍有效。

问题即契约：准则写可观测情境（如「动笔前需查外部证据」），勿用选项标签复读当准则。

接下来，第五部分，【方法/工具卡】七法则 + 决策闭环落地。

操作链路：Observe ，得到 Decide ，得到 Gate ，得到 Execute ，得到 Verify ，得到 Repeat；Jev 只选分叉，永不直接调工具。

法则要点：① 传证据 ② 问题契约 ③ 每步重建选项 ④ 同 state 多问题一次调用（文中 GDPR 例：快 10×、省 12×）⑤ 按置信度门控 ⑥ 权限/预算在代码 ⑦ 按整任务算成本。

置信度起步线：内部打标 0.70；Agent 交接 0.80；浏览器/工具 0.90；发布/支付/删除 ，得到 确定性检查 + 人工。

接入：Path A 原生 Jev API；Path B System One Adapter（OpenAI/Anthropic 垫片，概率校准不可互换，上线需重标阈值）。

立刻可做：把现有「让 LLM 输出 JSON 路由」改成 state schema + 1 个 Choice + 代码 gate；同一 state 下把紧急/欺诈/审批拆成并行 Noul。

接下来，第六部分，【避坑清单卡】五大反模式。

Prompt-as-State： state 里塞自然语言指令 ，得到 改显式字段。严重程度：小心。

Choice-as-Multi-Label： 多条件可同时成立却强行单选 ，得到 多个独立 Noul + 代码合并。严重程度：致命（路由错）。

DONE Without Proof： 模型说完成就停 ，得到 必须读文件/DB/页面做验收。严重程度：致命（Demo vs 生产的分水岭）。

Stale Action Menu： 环境变了菜单未更新 ，得到 每次决策前重算可用动作。严重程度：致命。

Confidence-as-Truth： 高置信当真理 ，得到 标定集定阈值 + Abstain + 高危人工。严重程度：致命。

接下来，第七部分，【决策/选型表】何时用 Jev / LLM / 纯代码。

邮件路由、技能挂载、浏览器点选，Jev Choice/Noul，候选有限、高频、进代码分支，长链 CoT 单 prompt，解析脆弱、贵且慢

写回复草稿、论文摘要，通用 LLM，需要可读散文与创意，Jev，非决策接口

时间戳加减、权限 bitmask，确定性代码，可证明正确，Jev/LLM，手册明确归代码

质量 linter 全量筛，Jev 并行 Noul + 边界 case 上大模型，Every 测：777 判 0.7s；漏 1/7 缺陷需二段，全篇 High-reasoning LLM，慢 25×、贵 580×

DOM 巨页逐节点 Score，先瘦候选再决策，Retriever 反例：决策便宜但前置膨胀致总成本 +38~51%，无脑扩大 state，端到端任务成本才诚实

接下来，第八部分，【跨概念对比表】Jev System One vs 通用 LLM 调用。

输入，结构化 state + 类型问题，自由 prompt，契约 vs 散文

输出，概率/置信度对象，长文本，零解析 vs 正则/JSON 提取地狱

并行，同 call 多问题（同 state），通常一问一 call，决策密度决定 ROI

调试，看分布与阈值，重读生成文，分叉可审计

计费，按决策次数，按 token，高频小判 Jev 占优

接下来，第九部分，【心法/原则卡】决策密度与 Harness 解耦。

原则，当单次决策边际成本，得到0，系统可在每条消息、每次工具调用、每次 handoff 都做判定——价值随频次复合增长。

数据锚点：Browser Use 调用 1092，得到101；500 封邮件 ~3.5¢；1,018 篇论文分类 ~0.08$（不含摘要 LLM）。

与 Google Harness Thesis： Jev 把 Harness 里最乱的「决策块」抽成显式类型接口，接口规范比底层权重更持久。

无人值守纪律：可逆步骤可自治；红线挂起；恢复先读最后一次外部确认成功的状态；置信度不能证明付款/发信已成功。

适用边界，基准来自公开 demo，阈值是冷启动线；Adapter ≠ 生产概率校准；闭源 Jev 需自有标定集。

接下来，第十部分，总结与行动。

结论

三层解耦 + Choice/Score/Noul 消灭「决策输出解析」类故障。

State 是证据、问题是契约；同 state 批量提问是性能杠杆。

代码门控权限与阈值；高危必须人工 + 确定性规则。

完工与成功以外部状态探针为准，不信模型 DONE。

方法论可脱离单一产品：类型契约 + 置信度 + 验证闭环即核心。

选一个高频路由（邮件/技能/模型选择），画 state schema 与 2–4 个原子问题。

用标注集标定置信度阈值并保留 Abstain/人工分支。

把「LLM 返回 JSON 分支」迁移为 gate 在代码、决策在 Jev/Adapter。

为 Agent 循环加 Verify 步骤：每步只执行一个可逆动作并重读 state。

用端到端单任务成本评估，避免只看单次 API 标价。
