接下来，第二部分，认知纠偏。

认知纠偏

误解：SoL-Pi = Agent 在线运行时自己改 Harness。实际是离线、模型固定、人类守两端的 L2 形态；不是全自治 RSI，留出集结果绝不回流训练。

接下来，第三部分，反驳。

反驳

对立视角：「手工调 Prompt 和工具 Schema 就够了，不必上 535 环境 + 152 想法的 SoL-Pi 重武器」

单点提示无法稳定 Action Fusion 触发率，也无法在双门与留出隔离下证明组合机制不牺牲 TB4/IMO 之外的泛化——SoL-Pi 卖的是可复制的离线搜索与防作弊验收，不是多写几条 System Prompt。

接下来，第四部分，【概念拆解卡】SoL-Pi 与 RSI Harness 定位。

在讲什么问题，编程 Agent 变强后，Token 冗余与「能否改生产 AI 系统本身」两条线如何同时推进？

关键理解，先让 AI 把 Harness 改得更省，再用更省的 Harness 支撑下一轮研究——SoL-Pi 是 RSI-inspired、作用于 Harness 层，观察轨迹、提出改动、双门验收。

和其他概念关系：L1 人工改 Harness ，得到 L2 SoL-Pi（AI 离线搜索 + 人审幸存者），得到 L3/L4 仍开放。

怎么落地用：固定能力指标与容差（对优化 Agent 不可见），再搜效率改进；535 环境训练，EdgeBench 留出隔离。

边界说明，不是运行时自改；开放式循环中目标漂移可能人类察觉前已累积；「递归高效改进」未实证。

原文依据，「与其先去规模化 RSI，不如先让 AI 把 Harness 变得更省，再让更省的 Harness 去支撑下一轮 RSI。」

接下来，第五部分，【跨概念对比表】L1～L4 Harness 改进形态。

谁主导，人看轨迹手改，AI 研究 Agent + 人审幸存，人退出，当前可落地在 L2

数据隔离，依赖工程习惯，训练/留出物理隔离、一次验收，未知，留出绝不回流是硬护栏

风险，慢但可控，搜索烧 Token、能力作弊，漂移难察觉，双门 + 冻结指标防作弊

SoL-Pi 证据，—，4 机制、EdgeBench 成本 −33%，未证明，省成本 ≠ 全面更强

接下来，第六部分，【方法/工具卡】四个幸存机制怎么切 Harness。

核心思路：152 候选经 Oracle 预筛与独立 autoresearch 循环，仅 4 个机制组合通过能力底线且改善效率。

操作步骤，① Action Fusion：编辑+测试命令合成一次工具调用（Schema 级稳定触发），得到 ② Online Context Compact：子任务边界算「省输入 vs 重写缓存」回本才压 ，得到 ③ ObservationPack：超大工具输出前两次全量、之后句柄+摘录 ，得到 ④ Evidence-Preserving Reducer：便宜模型压缩日志，确定性校验引用与哈希，失败回退原文。

选型条件，轨迹里相邻 edit+test 多、上下文膨胀、巨型 build 日志、重复工具输出时分别对应四机制。

避坑，单靠提示词融合动作触发不稳定——论文中改 Schema 才零无效调用；完整方案缓存写入反而增多，要看任务总账而非命中率。

原文引用：「不能只盯缓存命中率，要算整个任务的总账。」

接下来，第七部分，【决策/选型表】何时用完整 SoL-Pi vs 单机制。

优先降 API 成本、可接受 ~6% 得分损失，完整四机制组合，EdgeBench Token −49%、成本 −33%（对 Pi），只加 Context Compact，单机制得分可掉到 42.0

要保分又减轮次，+ Action Fusion，Opus 上得分 50.5（+12.8% vs Pi），跳过能力门，早停/删验证类作弊

TB4/IMO 要解题数，原生 Pi/Codex，SoL-Pi TB4 少 3 题、IMO Codex 5 vs 3，默认 SoL-Pi 最强，论文明确「更便宜不是更强」

多 Agent 集群，SoL-Pi worker，20 worker 周期 −17.5%、成本 −26.8% vs Pi 集群，单 Sol 当集群方案，单 Agent 仍最便宜

接下来，第八部分，【避坑清单卡】RSI Harness 搜索陷阱。

坑名，留出集结果回流修补候选。

原因，会直接过拟合公开基准，虚假泛化。

解法，冻结后留出集只评估一次，失败即淘汰。

严重程度，致命——科学性与上线信任。

坑名，养一个不断膨胀的实验协调器。

原因，YAML 工作流修边缘 case、主 Agent 写协调代码都曾拖垮迭代。

解法，一次性技能循环：最小模板复制、改参、跑完即丢。

严重程度，小心——规模化搜索会卡死在编排。

接下来，第九部分，【心法/原则卡】工程师 RSI Harness 七条清单。

原则，先声明再搜索；双门验收；训练/留出隔离；Oracle 预量化再分配 rollout；广度优先（约 1/40 转化率）；编排即用即弃；人守先验与幸存代码审阅。

为什么重要，模型迭代 5～10 轮易陷局部盆地，没有冻结指标则「省 Token」会变成少干活。

怎么落地，伪代码 accept(candidate)：门1 能力 ≥ baseline−容差；门2 至少一项效率改善；留出集函数冻结后只读一次。

适用边界，搜索轨迹目前主要在单一 Sol 后端；Opus 零调整迁移有效但 TB4 仍掉题。

原文支撑：「只有『不少干活』的节省才算数。」

接下来，第十部分，总结与行动。

结论

SoL-Pi 是 L2 离线 RSI-inspired Harness 改进，模型不变，人类提供先验并审阅 4 个幸存机制。

双门（能力底线 + 效率改善）与留出集一次验收是防作弊与过拟合的核心。

四机制分别优化动作合并、子任务上下文、大观测打包、日志委派压缩。

EdgeBench 上成本约降三分之一、对原生 Harness API 成本低 50%～54%，得分约保留 94%，但 TB4/IMO 解题数不占优。

工程师应复制「声明—搜索—隔离—即用即弃编排」流水线，而非只抄四个机制名。
