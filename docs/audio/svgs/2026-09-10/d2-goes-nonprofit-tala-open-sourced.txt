一句话概括。本文解决的核心问题是：当 D2 母公司 Terrastruct 关停后，项目如何通过 Hack Club 财务代管转型为完全非营利开源，TALA 正交布局算法为何在此时开源，以及创始人「全 AI 写代码 + 三不做」的产品哲学对 Agent 时代架构图生成意味着什么。

接下来，第一部分，核心概念关系。

关系脉络如下：Open-Core 时代，D2 免费 + Studio/TALA 付费，然后2026-09-05，Terrastruct 关停，捐赠 Hack Club，然后2026-09-07，TALA MPL-2.0 开源，v0.9.0 发布，然后下一阶段，AI 写代码 · 三不做

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「公司关停 = 项目死亡」。D2 通过 Hack Club（The Hack Foundation 501(c)(3)）财务代管，资金公开可查、创始人零报酬，赞助不影响路线图与 MPL-2.0 许可证——这是把项目存续与商业公司解绑的治理样本，而非简单的「项目被卖掉或放弃维护」。

接下来，第三部分，反驳。

反驳

对立视角：Mermaid 生态拥护者 · 「语法更成熟、社区更大，D2 转型只是垂死挣扎」

Mermaid 的 DAG 分层布局在 CI 自动更新场景更稳定，生态集成（GitHub、Notion、文档工具）碾压 D2；TALA 坐标锁定听起来美好，但大图性能和非线性重排让生产环境不敢押注——非营利 + 创始人兼职维护，反而比 Terrastruct 时期更不可信。

接下来，第四部分，【概念拆解卡】D2 非营利转型：从 Open-Core 到完全开源。

在讲什么问题，Terrastruct 关停后，D2 如何不靠闭源 Studio 和 TALA 继续生存？

核心机制，创始人将 D2 整体捐赠给 Hack Club 进行财务代管（fiscal sponsorship），项目转为独立、非营利、100% 开源；捐赠资金可抵税，去向完全公开，创始人和共同创始人不从基金中拿报酬。

关键理解，这不是项目易手，而是治理结构重构——把项目存续与单一营利公司命运脱钩，类似 Linux/Apache 基金会模式但更轻量。

典型场景，开源核心项目面临母公司战略调整或关停时，需要社区可持续维护路径。

边界说明，创始人坦言个人时间投入会比过去有限，高质量维护者可能通过捐赠资金获得合同报酬——适合有开源经验的早期职业开发者，但不保证全职团队规模。

原文：赞助 D2 不会影响路线图、治理或许可证；开发全程在 GitHub 公开进行。

接下来，第五部分，【概念拆解卡】TALA：专为架构图设计的正交自动布局算法。

在讲什么问题，TALA 和 Dagre/ELK 有什么本质区别？为什么现在开源？

核心机制，TALA（Terrastruct's AutoLayout Algorithm）走正交布局路线，优化对称性、节点间距、信息流向、同类聚类等多维美学指标；融合多篇图绘制论文思路加团队原创技术。D2 不再靠商业化生存后，闭源 TALA 失去意义，随 v0.9.0 以 MPL-2.0 同步开源。

关键理解，坐标可控是 AI 时代杀手特性——大模型擅长摆方块位置，走线排版仍靠算法兜底，TALA 支持部分或全部节点锁定 top/left，算法负责剩余布局与连线路由。

典型场景，系统全景类软件架构图、AI Agent 批量生成架构图后交给算法排版。

边界说明，不擅长长链路 DAG 流程图、有随机性（增删节点可能整体重排）、大图渲染非线性变慢。

落地命令：d2 --layout=tala architecture.d2 architecture.svg；也可在 play.d2lang.com 浏览器本地体验，无需服务器。

接下来，第六部分，【跨概念对比表】TALA vs Dagre vs ELK。

布局风格，分层、单向延展，适合长链路流程图，更接近白板手绘的正交布局，流程图选 DAG，全景图选 TALA

稳定性，增删节点后局部变化，整体形态基本稳定，有随机性，同种子结果一致，但加节点可能整体重排，需要图稳定不跳变时 TALA 是短板

坐标控制，算法全权决定，支持部分/全部节点锁定 top/left，AI 生成 + 算法排版混合模式是 TALA 独优势

性能，大图渲染相对线性，非线性增长，越大越慢，大规模图谱需注意基准测试

适用场景，长链路架构图、DAG 关系图，系统全景、对称美观架构图、Agent 生成图形，官方坦承某些图反而更喜欢非 TALA 布局

接下来，第七部分，【方法/工具卡】D2 下一阶段：全 AI 驱动开发的操作范式。

方法名：AI 写代码 + 人类写文字 · 标签：效率优先、坦诚争议

核心思路：创始人宣布手写代码时代结束，所有代码贡献由 AI 完成，社区 AI 贡献也由 AI 审核；唯一例外是博客和对外沟通 100% 人类撰写。

操作步骤，1) 用 AI 实现过去因人力有限搁置的功能（等距渲染器、其他画图语言转译器），得到 2) 社区可提交 AI 生成 PR ，得到 3) 维护者用 AI 交叉审核 ，得到 4) 主动引用 Neil Alexander「AI slop 灌水」争议文章，先丑话说在前面

落地建议：升级到 D2 v0.9.0，对现有 .d2 文件分别用 TALA / Dagre / ELK 渲染对比，GitHub 上有 7 个真实公开项目可供横向评测。

避坑：创始人不向任何人推荐 AI 灌水式贡献，但坦诚自己的计划——社区需关注 PR 质量而非数量，参考 Neil Alexander 直接关闭无实质投入 PR 的做法。

接下来，第八部分，【决策/选型表】布局引擎与产品边界选型。

长链路单向流程图，Dagre 或 ELK，分层延展稳定，增删节点局部调整，TALA，官方坦承不擅长 DAG 长链路

系统全景架构图，TALA，正交美学、对称聚类、多维优化，纯手绘像素，无法版本化与自动化

AI Agent 生成架构图，模型定坐标 + TALA 排版走线，大模型摆方块强、走线弱，混合分工，纯 LLM 端到端出图，走线交叉、间距不协调不可控

需要图布局稳定不跳变，Dagre / ELK，增删节点见缝插针，整体形态不变，TALA，加一节点可能整体重排

大规模图谱（数百节点），Dagre / ELK，线性性能，TALA 非线性变慢，TALA，官方提供 d2-benchmarks 仓库佐证

接下来，第九部分，【避坑清单卡】TALA 官方自曝的三条权衡。

坑 1 — 随机性导致布局跳变：默认 3 种子选最优，同种子结果一致，但增删节点可能整张图重排。Dagre/ELK 通常只是局部调整。

坑 2 — 不擅长 DAG 长链路：想要长长单向流动图时，官方自己更愿意用 Dagre 或 ELK。

坑 3 — 大图性能非线性：图越大 TALA 相对 Dagre/ELK 耗时差距越大，需参考 github.com/d2lang/d2-benchmarks 做基准测试。

严重程度：坑 1 在 CI/CD 自动更新架构图场景可能是致命的；坑 2/3 可通过场景选型规避。

接下来，第十部分，【心法/原则卡】三不做：拥抱 AI 效率但拒绝盲目扩张。

原则，在拥有更强 AI 生产力时，主动划清「能做」与「该做」的边界。

三不做清单：1) 不做臃肿万能画图工具（不加维恩图等偏离架构图定位的功能，未来用插件/模块外置），得到 2) 不在 D2 内置 LLM 对话套壳（模型看几个示例就能转 .d2，无需专门调教界面），得到 3) 不做任何服务端能力（不做 MCP、不做 API、不做账户系统、不做服务端渲染、不做多人协作；D2 Studio 纯客户端可离线）

为什么重要，D2 想成为 Agent 时代「文本生成图形」的标准底座——像 HTML 之于网页，你需要文本化图源代码作为最终产物底层依据，而非被 Agent 绕过的旧工具。

怎么落地，评估自家工具栈时，问自己：这个功能是否强化「文本 ，得到 可版本化图形」核心链路？是否需要服务器？是否只是把 LLM 套壳？

适用边界，适用于非营利、无商业服务器预算的开源基础设施项目；需要云端协作的场景需另寻方案。

接下来，第十一部分，总结与行动。

结论

Terrastruct 关停后 D2 通过 Hack Club 财务代管转型非营利，TALA 随 v0.9.0 以 MPL-2.0 开源——从 Open-Core 到完全免费的开源路径。

TALA 正交布局 + 坐标锁定是 AI Agent 生成架构图的最佳分工模式：模型摆方块，算法兜底走线与美学排版。

创始人「全 AI 写代码 + 三不做」构成克制的产品哲学：不做 MCP/API/LLM 套壳，专注文本化图源代码作为 Agent 时代图形基础设施。

TALA 有三条官方坦承的短板：随机性跳变、不擅长 DAG 长链路、大图非线性变慢——需按场景选型。

升级 D2 v0.9.0，对现有架构图分别用 --layout=tala、Dagre、ELK 渲染对比效果。

探索 AI 生成 .d2 源码 + TALA 坐标锁定的混合布局工作流，模型定关键节点位置，算法负责排版。

长链路流程图继续用 Dagre/ELK；系统全景和 AI 批量出图场景优先 TALA。

关注 D2 GitHub 上 AI 驱动开发的 PR 质量实践，评估是否适用于自家开源项目。

若认可非营利路线，可通过 hcb.hackclub.com/d2 捐赠（美国可抵税，资金用途公开）。
