一句话概括。本文解决的核心问题是：大团队引入 AI 编程后，标准如何机器可读、审查如何不流于形式、数千仓库如何统一步调——Cloudflare 用 11 个月搭出平台层（AI Gateway + 代理 Worker）、知识层（Backstage + AGENTS.md + Code Mode）与治理层（Codex RFC + 七 Agent 评审），把 24 万次违规标记与 1.6 万次强制拦截变成可复制的工程闭环，而非营销数字。

接下来，第一部分，核心概念关系。

关系脉络如下：平台层，Gateway+Worker，零信任 SSO，然后知识层，Backstage，AGENTS.md，Code Mode，然后治理层，Codex RFC，SHOULD/MUST，然后执行层，Spec/代码/事故，三类评审 Agent，然后CI 编排，协调者+7专科，风险分级路由

接下来，第二部分，认知纠偏。

认知纠偏

常见误解：「上了 Copilot 就等于 AI 工程化」。Cloudflare 的数据表明 95% 研发渗透率背后，真正拉开差距的是机器可读的工程宪法 + CI 原生编排，而不是给每个人发一个聊天框。

接下来，第三部分，反驳。

反驳

对立视角：「轻量 Copilot + 人肉 Code Review」的务实派

你们为 3600 人堆了 Backstage、3900 份 AGENTS.md、60+ RFC 和七 Agent 编排——前期「笨功夫」和运维复杂度，多数国内团队根本扛不住；真紧急时还得靠 break glass 放行，说明 AI 护栏在热修场景下仍是成本中心而非净增益。

接下来，第四部分，【概念拆解卡】三层 AI 工程栈各自解决什么。

在讲什么问题，AI 工具人人有，但标准散落 Wiki、审查靠人肉、Agent 不懂仓库上下文，产出天花板很低。

核心机制，平台层统一鉴权与成本；知识层用 Backstage 服务目录 + 约 3900 份 AGENTS.md 给 Agent「系统认知」；治理层用 Codex 把 SHOULD/MUST 抽成结构化 JSON，供评审 Agent 按需加载。

关键理解，难复制的是「接线方式」——当 Agent 能同时读 Backstage、AGENTS.md 和 Codex，第一版产出才接近可合并水平；六个月前做不到。

典型场景，3600+ 员工、5169 仓库、月均 20 亿次 Gateway 请求的大规模日常研发。

边界说明，体系建立在自研 Workers/AI Gateway 同网推理之上；小团队可缩小规模，但「先知识再能力、先结构化标准再自动化」的顺序不宜颠倒。

「这周我们发布的所有能力，就是我们内部 AI 工程栈本身在跑的东西。」——完全用对外产品吃自己狗粮

相关概念：与「买一个现成 AI Code Review SaaS」不同——Cloudflare 在开源 OpenCode 上自建插件化 CI 编排，只为接入 Codex、GitLab、遥测等内部约束。

接下来，第五部分，【方法/工具卡】代理 Worker：零 API Key 的统一控制平面。

核心思路：客户端不直连 AI Gateway，而是经 Access SSO ，得到 代理 Worker ，得到 Gateway，密钥只在 Worker 端按请求注入。

操作步骤，① 工程师执行 opencode auth login https://opencode.internal.domain ，得到 ② 拉取 .well-known/opencode 发现配置 ，得到 ③ Access SSO 拿 JWT ，得到 ④ 合并组织默认与本地个性化配置生效。

选型条件，多模型供应商、多团队、需 per-user 成本归因与动态模型目录时，代理模式优于客户端直连。

落地：后续加成本归因、模型目录更新、权限策略，只改 Worker 一层，不动各客户端配置。

避坑：让工程师本地存 API Key——密钥扩散后无法集中轮换、审计与权限精细化管理。

对比直连：代理多一跳延迟，但换来「控制平面」——Cloudflare 工程师原话：直连架构给不了这层控制力。

接下来，第六部分，【方法/工具卡】Code Mode：182 个 MCP 工具压成 2 个。

在讲什么问题，MCP Portal 聚合 13 个生产 MCP、182+ 工具后，仅 GitLab MCP 的 Schema 就占约 1.5 万 token（20 万上下文里 7.5% 预算在提问前耗尽）。

核心机制，Portal 层不再把每个上游工具定义塞给客户端，而是收敛为 portal_codemode_search 与 portal_codemode_execute，模型通过写代码发现与调用具体工具。

所以呢：无论 Portal 后挂多少 MCP，客户端永远只见两个工具，上下文占用不与工具数量线性增长。

边界说明，适合工具爆炸的内部门户；若只有两三个稳定 MCP，直接暴露工具可能更简单。

配套：Backstage 沉淀 2055 服务、544 系统、1302 数据库等元数据，Agent 不再「盲人摸象」只看眼前代码。

接下来，第七部分，【决策/选型表】MR 风险分级：别用梦之队审错字修复。

所以呢：按 diff 规模与敏感路径自动路由，既控制信噪比（平均每次评审仅 1.2 条发现），又把 Full 级成本压在可规模化范围（中位 $0.98、P99 $4.45）。

Trivial，≤10 行、≤20 文件，2（协调者+通用），约 $0.20，最小评审面

Lite，≤100 行、≤20 文件，4（+质量+文档等），中等，常规功能改动

Full，超范围或触及 auth/crypto 等，7+ 专科，约 $1.68，安全路径一律 Full，不论行数

接下来，第八部分，【跨概念对比表】模型分工：贵的只干最难的裁决。

一句话结论：不是模型越贵越好，而是分工越细、路由越准，规模化成本才能撑住——安全 Agent 年账单从预估 $240 万降到 Workers AI 档可承受水平。

顶级，Opus 4.7、GPT-5.4，协调者：去重、定严重度、最终裁决，推理要求最高的一环

标准，Sonnet 4.6、GPT-5.3 Codex，代码质量、安全、性能，重活但边界清晰的专科评审

轻量，Kimi K2.5（Workers AI），文档、发布影响、AGENTS.md，文本类任务；同网推理成本降 77%

接下来，第九部分，【避坑清单卡】Codex 与评审系统的关键陷阱。

坑 1：标准直接喂整库 Wiki——上下文爆炸且效果打折。解法：先 RFC 化 SHOULD/MUST，再抽 JSON 语句带 slug，按需加载全文。严重程度：致命。

坑 2：approved 即强制阻断——团队来不及消化新规则。解法：approved 仅提示，enforced 才拦 MUST 级合并。严重程度：小心（推行阻力）。

坑 3：Prompt 只写「该关注什么」——产出大量「正确的废话」。解法：安全 Agent 明确负面清单：不标极端前提理论风险、不标未改动代码既有问题。严重程度：致命（信噪比）。

坑 4：MR 描述 Prompt 注入——伪造 XML 边界注入指令。解法：过滤 </mr_body> 等边界标签。严重程度：致命（安全）。

别踩：把 git diff 粗暴塞进单 Prompt——Cloudflare 试过，幻觉语法错误与泛泛建议泛滥，与专科 Agent + 协调者架构对比鲜明。

接下来，第十部分，【心法/原则卡】标准机器可读，审查机器一致执行。

原则，提效与不降质不对立；降质往往因为标准没落地、审查流于形式，而非因为用了 AI。

为什么重要，四个月 24 万次违规标记、1.6 万次强制拦截、600 份技术方案评审——规模下人肉核对每一条 RFC 不可行。

怎么落地，① AGENTS.md 自动化流水线 + MR 内校验更新闭环；② 定制 Linter（oxlint 等）毫秒级机械规则；③ break glass 逃生舱（0.6% MR）保留人工紧急热修通道；④ 增量复审而非每次重头再审。

适用边界，工程细节（JSONL 输出、30 秒心跳日志、熔断降级）是为「CI 里跑几分钟的大模型任务」服务；个人小项目可简化插件与路由，但「负面清单 Prompt」仍值得保留。

「告诉大模型不该做什么，才是 Prompt 工程真正的价值所在。」

接下来，第十一部分，总结与行动。

结论与行动

Cloudflare 用自家 Workers/AI Gateway 搭平台，95% 研发渗透率背后是统一入口与同网开源模型降本，而非单纯采购账号。

知识层（Backstage + AGENTS.md + Code Mode）解决「Agent 知道什么」，是产出质量的前提。

Codex 把工程标准变成机器宪法，approved/enforced 两阶段避免一刀切引发抵触。

CI 原生多 Agent 评审：协调者 + 风险分级 + 模型分工 + 熔断/break glass/增量复审，中位 3 分 41 秒、$0.98。

为关键仓库起草 AGENTS.md：测试命令、目录约定、禁改区域、上下游依赖——可参考 Backstage 元数据自动初稿。

把团队规范整理成带 MUST/SHOULD 的结构化条目，再考虑喂给评审 Agent，而非直接丢 Wiki。

设计 MR 评审时划分 Trivial/Lite/Full 路由，敏感路径强制 Full，避免全量七 Agent 审小改动。

在专科 Agent Prompt 里写清「不该标记什么」，控制发现数量与信噪比。

阅读 Cloudflare 三篇官方工程博客（AI 工程栈、代码评审编排、标准强制执行）对照自身插件化与逃生舱设计。
